# 多方块 UI 迁移计划

## 功能映射

| 现有功能 | 当前实现 | LDLib2 实现 | 服务端契约 |
| --- | --- | --- | --- |
| 结构状态 | Screen 中逐行绘制 | `MultiblockStatusPanel` 的绑定 `Label` | 结构 formed 与失败原因只读同步 |
| 容量与 CPU 状态 | Screen 中文本裁切和颜色判断 | `ProgressBar` + `Label` + tooltip | 数值和展示文本 S2C |
| 合成目标 | Hover 区域手工命中 | 目标元素及 `HoverTooltips` | 目标和容量 S2C |
| 64 槽页码 | Toolbar `ToggleButton` | 图标按钮 + 已绑定页码标签 | 翻页服务端点击 |
| 退款 | `OutputSideActionButton` | 图标按钮 + 确认状态 | 退款服务端点击 |
| 自动建造 | `MultiBlockAutoBuildOverlay` | 可拖动非模态 `AutoBuildPanel`、等级选择、数值输入 | 保留 `TrinityDataCoreAutoBuildPayload` 或等价 RPC |
| XEI 结构预览 | 无 | 共用 `StructurePreviewUI` | 纯客户端快照，不改世界 |
| 子结构选择 | 三套 JSON 与 Screen 内固定列表 | 子结构 selector + 每项参数状态 | 结构 id、tier、repeat 明确分离 |
| AE 样板写入 | 无 | 普通 XEI 配方 transfer | 复用现有 AE Processing 编码 |

## 实施阶段

| 阶段 | 工作 | 产物 | 完成条件 |
| --- | --- | --- | --- |
| M1 | 新建多方块 LDLib2 UI 入口与只读状态页 | 结构状态、容量、故障 tooltip | 与旧屏幕显示值逐项一致 |
| M2 | 迁移 Pattern Core 分页和退款 | 页码、64 槽绑定、退款按钮 | 翻页和退款在多人环境正确且不可越权 |
| M3 | 迁移四个主机子 UI | `main`/`cpu`/`crafting` 结构窗口与独立自动搭建窗口 | 四窗生命周期独立且请求参数与旧 overlay 完全等价 |
| M4 | 接入通用 XEI 预览 | JEI/EMI 类别、子结构/等级/层数/切片控件 | 两端使用同一预览模型且材料一致 |
| M5 | 接入 AE 样板写入 | JEI/EMI transfer、Processing 模式与错误反馈 | input/output 与当前 XEI 配方一致 |
| M6 | 删除旧多方块 Screen/overlay 引用 | 注册与资源清理 | 无旧入口、无功能回退 |

## 四个 Provider 边界

| Key | 状态来源 | UI 职责 | 唯一允许的业务动作 |
| --- | --- | --- | --- |
| `main` | 客户端 `TrinityDataCoreMenu` 的 online、main formed/matched/failure、storage type/amount/capacity 同步字段 | 展示主机与主结构状态，并创建独立主结构预览 view state | 无世界或库存写入 |
| `cpu` | 菜单的 CPU formed/matched/failure、partition/busy partition、storage bytes、co-processors、busy crafting CPU 字段 | 展示 CPU 子结构和容量；明确区分全网 busy crafting CPU 与 Trinity CPU partition | 无世界或库存写入 |
| `crafting` | 菜单的 crafting formed/matched/failure、P Core count/capacity、crafting target、refundable 状态 | 展示合成子结构、目标 tooltip 与退款按钮 | 退款仅调用 `menu.sendRefundAll()`，由既有服务端 client action 调用 host |
| `auto_build` | 每次打开重新取得 preview catalog/spec；窗口内保存三结构各自 tier/repeat 暂存状态 | 选择结构、tier/repeat、展示权威计划并显式确认 | 把选择映射为既有 `TrinityAutoBuildRequest`，只发送 `TrinityDataCoreAutoBuildPayload` 或等价服务端入口 |

provider 不读取客户端 BlockEntity，不缓存跨 revision 的 spec，也不共享元素树、`Scene`、dummy world 或拖动状态。四个 provider 可以共同委托纯 `StructurePreviewUiFactory`，但 host 和 XEI 必须各自创建新的调用上下文及运行时资源。

## 自动建造细节

Trinity 多方块主机共有四个独立子 UI：`main`、`cpu`、`crafting` 三个结构窗口和一个自动搭建窗口。四窗可同时打开并独立拖动，点击窗口提升 z-order，Esc 每次只关闭最上层窗口；关闭和重开任一窗口不得影响其他三个窗口的选择、位置或资源。

`MultiBlockAutoBuildOverlayDescription`、其 `Structure` 和 `TierOption` 应保留为纯描述模型。`AutoBuildPanel` 仅维护暂存选择，点击确认时一次性生成 `MultiBlockAutoBuildSelection`，再转换为现有 `TrinityAutoBuildRequest`。自动搭建作为第四个 provider 通过 host 扩展层非模态挂载，不作为结构窗口页签。关闭时必须 `removeChild`，重开时创建全新元素树，不复用旧监听器、拖动对象或其他窗口实例。

必须在服务端重新验证：structure key/variant、definition revision、repeat count 的上下界、tier 是否存在、玩家距离与权限、目标区块已加载、物品库存、方块可替换性、结构世界状态、菜单/host 仍有效，以及 lifecycle/request sequence 未重复或乱序。任一恶意或过期请求失败时不得写世界、部分消耗材料或保留半完成 session；客户端禁用按钮只用于体验，不能构成校验。

## 验收矩阵

| 场景 | 断言 |
| --- | --- |
| 未成型、成型、部分失效 | 状态颜色、失败文本、失败位置和 tooltip 正确 |
| 三个 Trinity 子结构 | 主/CPU/合成容量与目标显示不串位 |
| 多页模式核心 | 上下页边界禁用正确，64 槽页面内容正确 |
| 自动建造取消与确认 | 取消零副作用；确认只发一次合法请求 |
| 四个主机子 UI | 可同时打开、独立拖动和置顶；连续 Esc 按 z-order 逐个关闭，重开得到全新实例 |
| JEI/EMI 多方块页 | 结构可旋转缩放，子结构、等级、重复层数和显示层互不串状态 |
| XEI 材料 | 选择变化后 ingredient、数量与自动建造计划一致 |
| AE 样板 | recipe transfer 后终端 input/output 与页面一致，编码走既有原子流程 |
