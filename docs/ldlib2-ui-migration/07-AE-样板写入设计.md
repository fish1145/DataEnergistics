# AE 样板写入设计

## 已确认语义

严格沿用 GT/ECO 的 XEI 多方块 recipe wrapper 思路。给定当前子结构、tier 和 repeat 后，结构投影自动产生一份普通 XEI 配方：

| 配方角色 | 内容 |
| --- | --- |
| input | 展开结构所需材料，按 ItemStack 组件归一化并合并数量 |
| output | 该多方块定义的控制器/owner 物品，数量为 1 |
| recipe id | controller id 加稳定的选择摘要，或由 wrapper 提供等价稳定标识 |

这不是 AE 专属配方、不是新的建造蓝图 item，也不新增 AE pattern details。写入 AE 样板的含义是：把这份普通配方通过 JEI/EMI transfer 填入 AE Pattern Encoding Terminal 的 Processing 输入/输出，然后复用项目现有编码按钮和 `PatternDetailsHelper.encodeProcessingPattern` 流程。

样板是通用材料配方，不是结构状态快照。不得将子结构 id、tier、repeat、显示层、formed、方向、镜像或逐方块 `BlockState` 属性编码进样板；这些状态只服务于预览或实际搭建。搭建发生时，由服务端按权威结构定义和本次搭建请求自动生成需要放置的精确状态。

## 转换链路

1. `PreviewSelection` 经过结构投影生成 `StructurePreviewSnapshot`。
2. recipe mapper 从快照取得材料汇总，并从定义取得 controller/owner output。
3. LDLib2 材料 `ItemSlot` 标为 XEI input，控制器槽标为 XEI output。
4. JEI/EMI typed transfer handler 直接读取点击瞬间的 `currentRecipeView()`，先验证 revision、81 input/27 output 容量、空栈和数量；只有全部通过后才切换 Processing 模式并填充配置槽。
5. 玩家使用既有编码操作生成普通 AE Processing Pattern；空白样板、覆盖和网络库存行为完全沿用现有菜单。
6. 后续实际搭建若消费该通用材料关系，精确放置状态必须现场从结构定义解析，不能从 AE 样板反序列化。

## 参数与显示层

子结构、tier 和 repeat 会改变普通配方，因此 transfer 必须读取点击时的当前 recipe view。显示层、相机、hover、选中方块和 formed toggle 只是视图状态，不改变 input/output。

若同一控制器页面允许配置多个子结构，默认 transfer 当前正在预览的子结构配方，而不是隐式合并全部子结构。若 UI 提供“组合结构”页签，它可以显式生成合并后的另一份普通配方，但必须去重共享材料并在标题中清晰标识。

## 容量与候选规则

1. input 按 `ItemStack.isSameItemSameComponents` 等价语义聚合，不能只按 item id 合并。
2. predicate 有多个候选时，recipe view 使用当前选定候选；未选定时使用定义提供的稳定默认候选。
3. 输入种类超过 81 或输出种类超过 27（以及目标终端实际容量更小时），transfer 必须在任何菜单变更前返回可见错误，不截断、不拆成语义不完整的多个样板。
4. 数量超过单个 `GenericStack` 可表示范围时 Fail Fast；不得静默饱和或溢出。
5. 资源重载后 recipe view 失效并重建，旧页面不得 transfer 已过期材料。

## 复用现有编码入口

Data Energistics 已有普通 Pattern Encoding Terminal、Universal Pattern Encoding Terminal 的 Processing 编码，以及 JEI/EMI transfer 后的 source/key/fluid 记忆逻辑。新实现应提供正常的 typed recipe/ingredient 入口让这些逻辑消费，不新增反射，不直接写 `encodedPatternSlot`，也不复制空白样板消耗逻辑。

LDLib2 的 JEI recipe setup 会固化 ingredient，EMI wrapper 也会缓存 inputs/outputs，因此它们只负责页面展示。动态选择的 transfer 权威来源必须是 wrapper/session 暴露的 typed `currentRecipeView()`；显示层、相机或 ingredient cache 均不能参与 transfer。

## 验收矩阵

| 场景 | 断言 |
| --- | --- |
| 默认子结构 | XEI input 等于快照材料，output 等于 controller/owner |
| 修改 tier/repeat | 页面材料与 transfer 后终端槽同时更新 |
| 修改显示层 | 配方与终端槽不变 |
| JEI 与 EMI | transfer 后得到相同 Processing input/output |
| 候选方块切换 | 配方只替换对应材料，数量重新归一化 |
| 超出终端容量 | 显示 transfer 错误，终端原状态不被部分覆盖 |
| 成功编码 | 走现有菜单流程，恰好产生一份普通 AE Processing Pattern |
