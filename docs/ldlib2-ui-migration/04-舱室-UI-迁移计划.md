# 舱室 UI 迁移计划

## 类型与复杂度

| 舱室类型 | 现有菜单语义 | LDLib2 页面 | 风险等级 |
| --- | --- | --- | --- |
| `INPUT` | 7 行物品、流体/Key 假槽、升级、可选行 | 独立输入仓容器屏幕：固定库存网格 + 升级侧栏 + 解锁行状态 | 高 |
| `OUTPUT` | 7 行物品、流体/Key 假槽、升级、可选行 | 独立输出仓容器屏幕：固定库存网格 + 升级侧栏 + 解锁行状态 | 高 |
| `ME_INPUT` | 5x5 配置假槽与 buffer 实槽，当前固定全开 25 对 | 双列网格 | 高 |
| `ME_OUTPUT` | 36 个只读展示槽 | 只读展示网格 | 中 |
| `PATTERN_BUFFER` | 54 pattern、展示、催化剂、流体/Key 假槽，当前固定全开 | 分区面板 + 共享催化剂区 | 高 |

这五种类型均由各自的 `CompartmentMenu`/Screen 打开为独立容器界面，不挂到 Trinity `HostUiExtension`，也不要求窗口拖动、置顶、级联或 hosted-window 位置保存。这里的“独立”指菜单、槽 wrapper、`ModularUI` 根树和生命周期实例互不共享；INPUT/OUTPUT 可以复用同一 `CompositeWarehousePanel` factory。

## 槽位绑定原则

1. 保持 `CompartmentMenu` 中的 `SlotSemantic` 作为逻辑分组来源；迁移期不可用屏幕坐标推断槽位类型。
2. 每个 `AppEngSlot`、`FakeSlot`、`OptionalFakeSlot` 和 `RestrictedInputSlot` 必须绑定原菜单已经创建的 `Slot`，并映射为明确配置的 `AeItemSlot`。AE2 的流体/Key fake slot 仍是 AE2 fake-slot 输入协议，不得替换为 LDLib2 `FluidSlot`。
3. INPUT/OUTPUT 组合仓库的容量门控仍由服务端计算。客户端绑定 `unlockedSlotCount` 与 `unlockedRowCount` 后，仅改变元素可见性/禁用态，不得改变库存规则。ME_INPUT 与 PATTERN_BUFFER 虽复用 gated slot 包装，当前值分别固定为 25 和 54，迁移不得擅自新增升级语义。
4. 玩家背包必须绑定原菜单的 `PLAYER_INVENTORY`/`PLAYER_HOTBAR` semantic，禁止用 `InventorySlots` 重建 36 个玩家槽。
5. 先实施只读 `ME_OUTPUT`，随后实现 `ME_INPUT`，最后处理组合仓库与模式缓冲的可选槽、升级和复杂假槽。

## 分阶段计划

| 阶段 | 目标类型 | 工作内容 | 验收重点 |
| --- | --- | --- | --- |
| C1 | 共用骨架 | 标题、背景、玩家背包、槽位面板基类、样式 | 玩家背包所有基础点击行为正常 |
| C2 | `ME_OUTPUT` | 36 展示槽与数量刷新 | 只读、滚动/tooltip、网络库存刷新正确 |
| C3 | `ME_INPUT` | 配置/缓冲双网格与既有固定解锁状态 | 25 对槽语义与交互一致 |
| C4 | 组合仓库 | 7 行、流体/Key、升级区和可选行 | 行解锁、升级上限、假槽行为正确 |
| C5 | `PATTERN_BUFFER` | pattern、聚合展示、催化剂和双流体区 | 每个库存语义正确，54 pattern 槽全开 |
| C6 | 清理 | 删除旧手绘视觉树；保留 `Ldlib2AeProtocolScreen`/`CompartmentScreen` 薄壳、现有菜单类型与 Screen 注册 | 无重复绘制、无旧视觉入口、无遗留 mixin 依赖 |

## 当前实施状态

以 `b5780774` 为当前实现锚点，C1-C6 的生产迁移与入口切换均已按功能提交：`5879e48e` 迁移 ME 输出、`804cbb90` 迁移 ME 输入、`1d06ab5a` 迁移 INPUT/OUTPUT 组合仓库、`01cf140a` 迁移模式缓冲；`cd7577ad` 进一步统一了五类界面的标题、状态和组合仓升级侧栏，文档提交位于实现锚点之后。实现继续复用原菜单槽和 `SlotSemantic`，没有把 AE fake slot、容量、升级或物料规则复制到客户端 UI。

`CompartmentHostUi` 为五类根树创建固定标题、类型状态和玩家背包标题：INPUT/OUTPUT 显示解锁行，ME_INPUT 显示配置到 buffer 的关系，ME_OUTPUT 与 PATTERN_BUFFER 明确只读语义。所有标题/状态标签采用固定区域、`HOVER_ROLL` 和 overflow hidden；`CompositeWarehousePanel` 把升级槽放入带标题和边框的独立侧栏，同时保持原 `RestrictedInputSlot` 规则。

`cd7577ad` 同步扩展了四组舱室 GameTest（INPUT/OUTPUT 共用组合仓测试）及 `CompartmentUiTestAssertions`，覆盖翻译键、状态参数、固定 header 几何、升级侧栏几何、overflow 策略、槽 wrapper 身份与菜单索引。最终 `spotlessCheck compileJava compileTestJava test runGameTestServer build --no-daemon` 已通过，服务端 GameTest 为 `367/367`；客户端启动依赖已解决，但舱室客户端矩阵仍未完成。

服务端 GameTest 不执行最终客户端 Taffy layout，只能验证槽 wrapper/菜单索引、元素树和由生产常量计算的静态几何。隔离的 `clientTest` runtime 已能进入世界并完成插件初始化；用户已确认不新增客户端自动测试，渲染 bounds、tooltip、Shift-click、槽内拖拽分配和 fake-slot 点击协议按 [手工验收表](09-客户端与多人手工验收.md) 在客户端与多人环境验证，不得把启动或服务端测试结果表述为这些行为已经通过。

## 普通样板与搭建状态边界

舱室 UI 只展示并操作其既有菜单库存，不参与多方块配方身份或自动搭建状态。XEI 写入的是通用普通 Processing 配置，transfer 不编码样板，也不保存结构方向、镜像或精确 `BlockState`；只有玩家在 `auto_build` 子 UI 确认实际搭建时，服务端才按当前权威结构、选择和世界条件补全放置状态。不得从舱室槽或普通样板反推搭建状态。

## 特殊回归项

| 行为 | 必测原因 |
| --- | --- |
| Shift-click、双击收集、拖拽分配 | AE2 自定义 Slot 可能与原生容器行为不同 |
| `FakeSlot` 配置和清空 | 不能被当作普通物品槽处理 |
| Optional 行显示 | `isSlotEnabled`、`isRenderDisabled` 与容量同步必须一致 |
| 升级槽取放 | 受容量保护的升级库存不能绕过限制 |
| 断线、区块卸载、宿主替换 | holder 的 `stillValid` 必须关闭无效容器 |
| 独立容器生命周期 | 五种类型各自创建并释放菜单、wrapper 和根树；不注册 hosted-window 拖动或级联状态 |
| 标题、状态与升级侧栏 | 文案不越界，状态参数实时更新，组合仓升级标题与槽均落在侧栏静态几何内 |
