## 风险与约束

1. 目标菜单继续使用 AE2 `MenuTypeBuilder`、`MenuOpener` 和 `AEBaseMenu`；不迁移到 `BlockUIMenuType`/`ModularUIContainerMenu`。LDLib2 通过现有菜单的 `IModularUIHolderMenu` 能力挂载 `ModularUI`，从而保留 AE2 fake-slot、quick-move 和同步语义。
2. `ItemSlot` 绑定的是 Minecraft `Slot`。底层槽已存在于 `menu.slots` 时，单独调用 `ItemSlot.bind(existingSlot)` 不会登记 LDLib2 的 Slot-to-ItemSlot 映射；必须由显式 AE menu bridge 检查重复后调用 `ldlib2$addSlot(itemSlot)`，且不得再次向菜单添加 Slot。
3. 当前 `@GuiSync` 字段由 AE2 菜单同步。完成切换后应改为 LDLib2 数据绑定或受控 RPC，不要同时维护两套可写状态。
4. 原自动建造覆盖层是可拖动、非模态子窗，并处理标题拖动、视口夹取、Esc 优先关闭和 XEI 排除区域；替换为 LDLib2 子视图后必须逐项保持，不能降级为静态页签或模态对话框。
5. GT/ECO 的 XEI 多方块页面已清晰展示结构、材料和 owner/controller，但两者都没有可直接照搬的完整 AE Processing writer，且已有 recipe role/数量语义差异。本项目借鉴其页面模式，自行定义一致的 input/output role 与 typed transfer，不新增样板数据协议。
6. Data Energistics 的三个 Trinity JSON 是独立结构定义；通用预览层需要控制器到子结构集合的显式注册或发现接口。
7. LDLib2 的 JEI ingredient 在 `setRecipe` 时固化，EMI ingredient 又有缓存；动态子结构/tier/repeat 页面不能把 ingredient supplier 当作 transfer 权威数据，handler 必须读取点击瞬间的 typed `currentRecipeView()`。
8. AE2 的 Processing recipe helper 会按终端槽数遍历并静默截断超量输入。多方块 transfer 必须在修改模式或槽位前检查协议上限，并使用目标终端真实 `ConfigInventory.size()`、`isAllowedIn()` 与 `getMaxAmount()` 完整预检；不能硬编码容量后截断。
