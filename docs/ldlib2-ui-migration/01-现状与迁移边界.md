# 现状与迁移边界

## 现有实现盘点

| 分类 | 主要代码 | 当前职责 | 迁移处理 |
| --- | --- | --- | --- |
| 多方块状态 | `TrinityDataCoreMenu`、`TrinityDataCoreScreen` | 主/CPU/合成结构状态、容量、故障文本、合成目标 | 菜单的服务端状态来源保留，视图重写 |
| 模式核心 | `TrinityPatternCoreMenu`、`TrinityPatternCoreScreen` | 64 槽分页、退款、页码状态 | 业务菜单保留至替代容器稳定，视图重写 |
| 自动建造 | `MultiBlockAutoBuildOverlay`、`TrinityDataCoreAutoBuildPayload` | 选择结构、层数、等级后发送请求 | 描述模型与 payload 保留，覆盖层替换 |
| 多方块 XEI | 尚无多方块 JEI/EMI 类别 | 不存在通用结构预览、材料 ingredient 和结构 transfer | 新增共用预览模型和薄适配器 |
| AE 样板写入 | 已有普通配方到终端的 transfer 与 Processing 编码 | 多方块类别尚未暴露可 transfer 的 input/output | 让多方块 wrapper 进入现有 transfer 链路 |
| 舱室共用菜单 | `CompartmentMenu`、`CompartmentScreen` | 槽位创建、玩家背包、组合仓库容量门控与升级 | 槽位/库存规则保留，改为 LDLib2 Slot 绑定 |
| 舱室专用界面 | `CompositeWarehouseScreen`、`MeCompositeInputWarehouseScreen`、`MeCompositeOutputWarehouseScreen`、`MePatternBufferScreen` | 布局、标签、按钮和分页 | 按类型拆为 LDLib2 面板工厂 |

## 服务端边界

以下对象是权威业务层，UI 只能读取其状态或通过明确的服务端动作调用它们：

| 领域 | 权威对象 | 禁止迁移到 UI 的职责 |
| --- | --- | --- |
| 垂直多方块 | `VerticalMultiBlockController`、`VerticalMultiBlockRuntimeState` | 匹配、失效判断、结构扫描 |
| Trinity 自动建造 | `TrinityAutoBuildRequest`、自动建造服务及 payload handler | 参数校验、方块消耗、世界写入 |
| 舱室容量 | `CompartmentBlockEntity`、`CompartmentStorage` | 解锁数量计算、读写权限、库存聚合 |
| AE2 槽位 | `CompartmentMenu` 的 `AppEngSlot`/`FakeSlot` 规则 | 物品合法性、拖放、shift-click、同步 |

## 风险与约束

1. 目标菜单继续使用 AE2 `MenuTypeBuilder`、`MenuOpener` 和 `AEBaseMenu`；不迁移到 `BlockUIMenuType`/`ModularUIContainerMenu`。LDLib2 通过现有菜单的 `IModularUIHolderMenu` 能力挂载 `ModularUI`，从而保留 AE2 fake-slot、quick-move 和同步语义。
2. `ItemSlot` 绑定的是 Minecraft `Slot`。底层槽已存在于 `menu.slots` 时，单独调用 `ItemSlot.bind(existingSlot)` 不会登记 LDLib2 的 Slot-to-ItemSlot 映射；必须由显式 AE menu bridge 检查重复后调用 `ldlib2$addSlot(itemSlot)`，且不得再次向菜单添加 Slot。
3. 当前 `@GuiSync` 字段由 AE2 菜单同步。完成切换后应改为 LDLib2 数据绑定或受控 RPC，不要同时维护两套可写状态。
4. 原自动建造覆盖层是可拖动、非模态子窗，并处理标题拖动、视口夹取、Esc 优先关闭和 XEI 排除区域；替换为 LDLib2 子视图后必须逐项保持，不能降级为静态页签或模态对话框。
5. GT/ECO 已明确 XEI wrapper、材料 input 和控制器 output 的页面模式；本项目只需让这份普通 XEI 配方兼容现有 AE transfer，不新增样板数据协议。
6. Data Energistics 的三个 Trinity JSON 是独立结构定义；通用预览层需要控制器到子结构集合的显式注册或发现接口。
7. LDLib2 的 JEI ingredient 在 `setRecipe` 时固化，EMI ingredient 又有缓存；动态子结构/tier/repeat 页面不能把 ingredient supplier 当作 transfer 权威数据，handler 必须读取点击瞬间的 typed `currentRecipeView()`。
8. AE2 的 Processing recipe helper 会按终端槽数遍历并静默截断超量输入。多方块 transfer 必须在修改模式或槽位前完整预检 81 input/27 output 容量。

## 首轮迁移顺序

先迁移没有物品交互的 Trinity 状态面板和自动建造选择页，验证容器、S2C 同步与服务端点击；再迁移只有展示槽的 ME 输出舱室；最后迁移有容量门控和复杂交互的输入、仓库与模式缓冲舱室。
