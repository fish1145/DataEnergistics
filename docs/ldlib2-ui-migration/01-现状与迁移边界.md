## 已落地实现边界

1. P8 common/network、JEI 和 EMI 已在远端锚点 `d546ae7c` 之前按小提交完成，不再是工作区待集成内容。服务端依据当前 catalog 和 `projectionFingerprint` 重建普通配方视图，先按目标终端真实容量、filter 和数量上限预检，再以可回滚事务填入 Processing 配置。
2. transfer 不直接编码、不写 `encodedPatternSlot`、不消耗空白样板、不搬运材料。样板只保存最终普通 input/output；`structureKey`、`variantIndex`、tier/repeat、显示层、方向和具体 `BlockState` 不作为样板 metadata。实际搭建时才由服务端权威定义和当次请求补全方块状态。
3. JEI 与 EMI handler 以点击时的 `currentRecipeView()` 为权威。JEI runtime stop/start 会释放 `uiCache`；动态原料的 deferred refresh 最终通过公开 `showRecipes` 重建页面/formal slots，并接受导航历史增加。EMI 维护 live ingredients 和可扩容 slot pool。JEI 没有原位 formal-slot invalidation API，禁止以反射或私有实现规避。
4. 通用 XEI 页面由 JEI/EMI 共用纯 LDLib2 UI factory、候选栏和 owner output；子结构入口使用横向 scroller，按钮最小宽度 64px。recipe role 仅把规范化材料槽标为 `INPUT`、owner/controller 标为 `OUTPUT`，`Scene` 和交互控件保持 `NONE`。
5. host 提供 `main`、`cpu`、`crafting`、`auto_build` 四个可同时打开的独立子窗口。默认位置冲突时首次级联，保存/拖动位置优先；四窗各自拥有元素树、拖动位置、`Scene`、generation 和释放周期。
6. Trinity 四窗统一为 `292x210`，布局为 196px `Scene` 加 84px 状态/动作侧栏，launcher rail 使用 important z-index 400。舱室 UI 已覆盖 `ME_OUTPUT`、`ME_INPUT`、INPUT/OUTPUT 组合仓库和 `PATTERN_BUFFER`，保留原菜单槽位、容量与升级语义。

## 风险与约束

1. 目标菜单继续使用 AE2 `MenuTypeBuilder`、`MenuOpener` 和 `AEBaseMenu`；不迁移到 `BlockUIMenuType`/`ModularUIContainerMenu`。LDLib2 通过现有菜单的 `IModularUIHolderMenu` 能力挂载 `ModularUI`，从而保留 AE2 fake-slot、quick-move 和同步语义。
2. `ItemSlot` 绑定的是 Minecraft `Slot`。底层槽已存在于 `menu.slots` 时，单独调用 `ItemSlot.bind(existingSlot)` 不会登记 LDLib2 的 Slot-to-ItemSlot 映射；必须由显式 AE menu bridge 检查重复后调用 `ldlib2$addSlot(itemSlot)`，且不得再次向菜单添加 Slot。
3. 当前 `@GuiSync` 字段由 AE2 菜单同步。完成切换后应改为 LDLib2 数据绑定或受控 RPC，不要同时维护两套可写状态。
4. 原自动建造覆盖层是可拖动、非模态子窗，并处理标题拖动、视口夹取、Esc 优先关闭和 XEI 排除区域；替换为 LDLib2 子视图后必须逐项保持，不能降级为静态页签或模态对话框。
5. GT/ECO 的 XEI 多方块页面已清晰展示结构、材料和 owner/controller，但两者都没有可直接照搬的完整 AE Processing writer，且已有 recipe role/数量语义差异。本项目借鉴其页面模式，自行定义一致的 input/output role 与 typed transfer，不新增样板数据协议。
6. Data Energistics 的三个 Trinity JSON 是独立结构定义；通用预览层需要控制器到子结构集合的显式注册或发现接口。
7. LDLib2 的 JEI ingredient 在 `setRecipe` 时固化，EMI ingredient 又有缓存；动态子结构/tier/repeat 页面不能把 ingredient supplier 当作 transfer 权威数据，handler 必须读取点击瞬间的 typed `currentRecipeView()`。
8. AE2 的 Processing recipe helper 会按终端槽数遍历并静默截断超量输入。多方块 transfer 必须在修改模式或槽位前检查协议上限，并使用目标终端真实 `ConfigInventory.size()`、`isAllowedIn()` 与 `getMaxAmount()` 完整预检；不能硬编码容量后截断。
9. 服务端 GameTest 能验证窗口拓扑、生命周期、菜单槽 wrapper 和索引，但不能证明真实客户端 Taffy bounds、XEI formal slots、按钮交互或 `Scene` 渲染。客户端环境仍因 Oritech 缺少 Athena 运行时依赖而阻塞，禁止修改生产依赖或伪报客户端验收完成。
