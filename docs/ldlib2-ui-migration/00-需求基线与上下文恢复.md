## Gradle 与 Git 约束

1. Gradle 只能使用系统环境变量提供的 `GRADLE_USER_HOME`。执行前必须读取并记录其值；未设置时停止并报告，不能自行创建或重定向 `.gradle` 目录。
2. 不通过命令行 `-g`、项目属性、脚本或 IDE 设置覆盖系统环境变量。
3. 当前检测到的机器级 `GRADLE_USER_HOME` 为 `E:\.gradle`，但后续会话仍必须重新读取，不能依赖本文的历史值。
4. Data Energistics 与 Modular Data Lib 是独立 Git 事务。MDLib 只有在确认公共 API 缺口且用户重新授权实施时才建立独立分支、提交、推送和 PR。
5. Modular Data Lib 当前工作区已有未提交改动，实施者必须先审阅并区分来源；不得覆盖、暂存或提交非本任务改动。

## 术语固定

| 术语 | 含义 |
| --- | --- |
| 结构定义 | 一个可解析的多方块定义，例如 Trinity main。 |
| 子结构 | 同一控制器下可独立选择和配置的结构成员，例如 main、cpu、crafting。 |
| 等级 | 决定该子结构中可替换部件档位的业务参数。 |
| 重复层数 | 决定可重复结构段展开次数的业务参数。 |
| 显示层 | 只影响 3D 预览可见坐标的切片，不改变结构或材料。 |
| 预览快照 | 给定结构配置后生成的不可变相对坐标、谓词、候选、材料、边界和层信息。 |
| 多方块配方 | GT/ECO 风格的 XEI recipe wrapper；input 是结构材料，output 是控制器/owner 物品，不新增 AE 专属配方类型。 |
| XEI | JEI、EMI，以及未来可能接入的 REI 的统称。 |

## 已确认的配方语义

用户已确认不设计“AE 专属多方块配方”或“建造配置样板”。实现严格参考 GT/ECO 的 XEI 多方块页面：当前展开结构本身就是普通 XEI recipe wrapper，材料清单是输入，控制器/owner 物品是输出；AE 样板功能只是对该配方执行现有 transfer 和 Processing 编码。

样板必须保持通用：它不能成为结构选择或方块状态的序列化载体。预览可用精确 `BlockState` 渲染，材料映射只取可放置物品；执行自动搭建时才依据权威结构定义、当次 tier/repeat/方向等参数生成实际放置状态。
