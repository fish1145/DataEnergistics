## 术语固定

| 术语 | 含义 |
| --- | --- |
| 结构定义 | 一个可解析的多方块定义，例如 Trinity main。 |
| 子结构 | 同一控制器下可独立选择和配置的结构成员，例如 main、cpu、crafting。 |
| 等级 | 决定该子结构中可替换部件档位的业务参数。 |
| 重复层数 | 决定可重复结构段展开次数的业务参数。 |
| 显示层 | 只影响 3D 预览可见坐标的切片，不改变结构或材料。 |
| `structureKey` | controller 下具名子结构的稳定身份，例如 `main`、`cpu`、`crafting`。 |
| `variantIndex` | 同一具名子结构内部的稳定 shape/variant 选择，不等同于 repeat 或显示层。 |
| `visibleLayer` | `PreviewViewState` 中的显示切片；`ALL` 必须有明确表示，永不参与材料或样板。 |
| `registeredRecipeId` | XEI 注册时稳定的 controller 级 recipe id，不随页面内选择改变。 |
| `projectionFingerprint` | definition revision 与当前结构、variant、tier/repeat、候选选择共同形成的动态投影校验值。 |
| 预览快照 | 给定结构配置后生成的不可变相对坐标、谓词、候选、材料、边界和层信息。 |
| 多方块配方 | GT/ECO 风格的 XEI recipe wrapper；input 是结构材料，output 是控制器/owner 物品，不新增 AE 专属配方类型。 |
| XEI | JEI、EMI，以及未来可能接入的 REI 的统称。 |

## 已确认的动态窗口协议

1. `MenuTypeBuilder` 在服务端与客户端分别调用同一个菜单 factory；菜单完成 AE 槽创建后立即构造并挂载静态 host root。所有 sync value、RPC 和 message coordinator 必须以确定顺序注册，不能因物理侧、语言或本地配置改变注册拓扑。
2. 始终挂载的 root coordinator 传输 `{operation, key, sequence}`。客户端只提交 request；服务端验证 provider key、宿主有效性和当前 membership 后先 open/close 自己的动态树，再返回 ack；客户端仅按匹配 ack 应用同一操作。拒绝或乱序响应不得改变客户端树。
3. 关闭按钮和 Esc 都必须走 coordinator，不能先在客户端 `requestClose()` 移除按钮所属树。LDLib2 2.2.8 会在本地 listener 之后才发送元素级 server RPC，先移除会导致发包入口消失并留下服务端窗口。
4. LDLib2 sync/RPC ID 按注册顺序单调分配，移除后不复用。双方必须按相同 sequence 执行 open/close/reopen，provider 每次返回新的树；不同步的相机、拖动位置、z-order、hover 和 `visibleLayer` 只保留在客户端。
5. coordinator 是静态同步协议节点，不是隐藏浮窗。ECO 的预挂载 `display: none` 模式只可参考 factory/binding，禁止用于本项目四窗生命周期。

## 已确认的配方语义

用户已确认不设计“AE 专属多方块配方”或“建造配置样板”。实现借鉴 GT/ECO 的 XEI 多方块页面展示方式，并由 Data Energistics 明确定义普通 recipe view 与 typed transfer：当前展开结构的规范材料清单是输入，控制器/owner 物品是输出；AE 样板功能只是对该配方执行现有 transfer 和 Processing 编码。GT/ECO 均不能作为完整 AE writer 的既成实现。

样板必须保持通用：它不能成为结构选择或方块状态的序列化载体。`structureKey`、`variantIndex`、tier/repeat 和候选选择只通过最终普通 stack/amount 影响样板内容，其身份值不进入样板。预览可用精确 `BlockState` 渲染，材料映射只取可放置物品；执行自动搭建时才由独立且经服务端校验的 build request 携带结构与搭建参数，并依据权威定义生成实际放置状态。
