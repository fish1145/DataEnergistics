## 测试策略

| 层级 | 内容 |
| --- | --- |
| 纯逻辑测试 | 自动建造选择到 request 的转换、容量门控映射、分页边界、展示格式化。测试必须直接调用目标逻辑。 |
| 容器集成测试 | 方块 holder 有效性、菜单打开/关闭、服务端按钮授权、库存及假槽操作。 |
| 双端拓扑测试 | 分别构造 server/client 菜单树，断言 sync/RPC 注册顺序、初始数据 round-trip、动态 open/close/reopen sequence 与单调 ID 一致。 |
| 客户端手工测试 | 布局、tooltip、缩放、XEI 排除区域、鼠标键盘焦点、多人同步。 |
| XEI 一致性测试 | JEI 与 EMI 对同一选择生成相同快照、材料和样板请求；显示层切换不改变材料。 |
| 样板编码测试 | transfer 后输入/输出、Processing 模式、空白样板消耗、目标槽竞争和菜单失效。 |
| 回归测试 | 旧 UI 与新 UI 在同一存档、同一宿主状态下显示和行为一致。 |

AE transfer 的边界值必须覆盖 81 个输入成功与 82 个输入原子失败；失败时 Processing 模式和全部原槽内容保持不变。JEI/EMI 在 tier/repeat 更新后的下一次 transfer 必须立即读取新 recipe view，不允许使用 ingredient 缓存中的旧材料。

动态窗口测试必须覆盖：open request 经服务端 ack 后两端各创建一次；close 按钮和 Esc 在发 request 前不移除客户端树；拒绝、重复和乱序 sequence 不改变 membership；close/reopen 两端注册 ID 同步单调增长；四窗并行打开后按 z-order 关闭；菜单失效或断线时两端释放资源。不得用预挂载隐藏窗口让测试绕过动态注册。

自动搭建恶意请求必须覆盖未知 `structureKey`/`variantIndex`、越界 tier/repeat、过期 definition revision、伪造或重放 sequence、距离/权限不足、区块未加载、库存检查后变化、目标方块冲突及菜单/host 已替换。每个失败断言同时验证世界零写入、库存零净消耗、无残留 build session，并有包含玩家、host 和请求参数的日志。

## 每个提交的门槛

1. 所有源码 UTF-8 无 BOM；新增 Java 代码仅使用 import，不写完全限定名。
2. 新增公共接口按项目规范提供类和成员动机注释；不使用反射处理 AE2 或 LDLib2 访问问题。
3. 新功能的服务端状态变更均有权限、宿主有效性和参数校验；异常记录有上下文日志。
4. 执行与变更匹配的 Gradle 测试，并在客户端验证 UI 非空、交互可用。
5. 当前 Data Energistics 与 MDLib 分支均已明确授权继续推送现有 Draft PR；新增仓库或扩大 Git 范围仍需重新确认。提交信息遵循仓库既有 Git 风格。
6. Gradle 只使用系统 `GRADLE_USER_HOME`；未设置或不位于 `E:/` 盘则不构建，不创建任何替代缓存目录。
7. 清理本次新增或直接修改代码中的冗余 `Objects.requireNonNull`，仅保留公开不变量、延迟 supplier 或确有必要的过滤校验。
8. 所有 LDLib2 行为以 `2.2.8` source jar 为准；不得从 ECO `2.2.1` 或工作区 `2.2.28` 搬用未经核对的 API。含动态元素的提交必须证明 client/server 注册拓扑和 sequence 一致。
9. 对 `removeChild`、`REMOVED`、`MUI_CHANGED` 与资源释放做 fault-injection；异常后 host 必须 terminal，后续资源继续尝试释放，残留树不得复用或通过反射修补。

## 回滚条件

出现任一情况时保留旧 UI 注册并停止扩大迁移：物品重复/丢失、可绕过升级或容量限制、client/server 窗口树或 RPC ID 分歧、多人状态不同步、自动建造参数被客户端伪造后仍获执行、LDLib2 清理异常后继续复用残留树、XEI 交互被遮挡且无法修复。每个工作包独立提交，确保可按工作包回退。
