# 动作与状态反馈

## 1. hosted window 状态

### launcher 主点击

当前 `requestToggle` 会把已打开但被遮挡的窗口关闭。建议改为：

```text
closed  --click--> requestOpen
open    --click--> bringToFront
open    --X/Esc--> requestClose
```

launcher Button 使用以下状态类：

| 状态 | 表达 |
| --- | --- |
| closed | 默认样式 |
| open | active 描边/底线 |
| front | 更强的 focus/selected 状态 |
| warning/error | 图标旁状态点加 tooltip/narration |
| pending | spinner 或脉冲 opacity，Button 禁用 |

不需要为这些状态新增图像，全部由 LSS class、颜色、描边、opacity 和 LDLib2 通用图标表达。

## 2. pending 与 action result

当前 hosted request pending 会阻断子 UI 的鼠标、拖动和 Esc。UI 必须显式说明原因。

### 统一状态机

```text
IDLE
  -> SUBMITTING
  -> ACCEPTED / REJECTED
  -> IDLE
```

### Modular UI 反馈

- `SUBMITTING`：目标窗口显示非模态 busy overlay，禁用 recipe-affecting 控件和动作按钮。
- `ACCEPTED`：显示短时成功 Label，并刷新权威状态。
- `REJECTED`：保留当前草稿，显示本地化原因和可重试入口。
- launcher 和窗口内动作区使用同一 pending source，不能一处忙碌、一处仍可点击。
- 生产 UI 必须消费菜单已保存的 hosted action result；不能只等待 pending 消失。

## 3. CPU 任务跳转

CPU 子 UI 的“在 AE 中查看”是有副作用的菜单导航，也必须使用 pending/action result：

```text
SELECTED
  -> OPENING_AE_CPU
  -> OPENED / REJECTED
```

- `OPENING_AE_CPU`：锁定重复点击，但不冻结 Scene；按钮显示 pending Label/通用 loading icon。
- `OPENED`：以服务端打开 AE 菜单作为成功事实，Data Core 菜单按正常容器生命周期移除。
- `REJECTED`：保持当前任务选择并显示原因，例如任务已完成、CPU 已重建、grid 已变化或无访问权限。
- 请求携带稳定 CPU number 与 task revision；AE 私有 serial 只能在服务端打开菜单的当次解析中使用，不能成为客户端持久身份。
- 不允许客户端直接切换 Screen，也不允许为跳转失败提供“随便打开第一个 CPU”的兜底。

具体菜单与数据契约见 [05-存储CPU与合成增强.md](05-存储CPU与合成增强.md)。

## 4. 故障定位

主界面的故障摘要应是 Button，不是只能 hover 的 Label。

点击流程：

1. 根据 failure source 选择 `main`、`cpu` 或 `crafting`。
2. 窗口关闭时请求打开；已打开时置顶。
3. failure position 能映射到 snapshot 时，选择对应方块。
4. layer selector 切到该方块所在逻辑层。
5. Scene 下方 `检查` Dock 选中该位置并显示摘要；点击摘要后由 root-mounted popup 显示坐标、角色、候选和具体失败原因。

映射失败时仍打开正确窗口并显示原始服务端坐标/原因，不静默丢失。

## 5. 自动搭建

### P0：明确为单目标操作

当前 UI 为多个子结构保存“执行搭建”，但 submission 和服务端只执行当前结构。这会形成批量搭建错觉。

本轮建议：

- 只有当前预览的 structure 是提交目标。
- 其他 structure 只保留各自 tier/repeat 草稿。
- 移除每结构“执行搭建”开关。
- 不执行时不发送空请求。
- 主按钮动态显示“搭建主结构”“搭建 CPU 子结构”或“搭建合成子结构”。

未来若支持批量搭建，必须另行定义目标列表、依赖顺序、整体材料事务和回滚。

### 提交前检查视图

`检查` Tab 使用 `ScrollerView` 显示：

- 目标 structure。
- tier、repeat、candidate 摘要。
- 材料种类和总量。
- 主结构前置条件。
- 距离、权限、区块和目标空间状态。
- 最近一次服务端结果。

CPU/crafting 需要主结构先形成时，UI 提前禁用动作并显示原因。

### 提交与确认

1. 第一次点击“搭建当前结构”进入窗口内确认状态。
2. 确认区显示目标、材料和世界写入提示。
3. 第二次确认才发送 submission。
4. pending 时保存提交快照，右侧显示“正在搭建 CPU T2 x4”。
5. 用户仍可旋转 Scene 和切换 layer，但不能改变 structure/tier/repeat/candidate。

### 失败结果

服务端结果至少包含：

- 结构化失败类别。
- 首个失败坐标。
- detail。
- 是否可重试。

UI 不能把单个失败简单显示成“缺少 1 个”或“阻挡 1 个”而丢失实际位置与原因。

## 6. crafting window 退款

- Data Core crafting window 使用 Data Core 专用退款文案。
- 动作 Button 固定在 `合成详情` 页底部，与详情 scroller 分离；不得增加第三个顶层页。
- Button 显示 refundable、pending、completed/rejected 状态。
- tooltip 说明优先进入 AE 存储，随后才是背包或世界掉落。
- pending 时禁止重复提交，但不锁死 Scene 观察。

## 7. Pattern Core 退款

Pattern Core 当前 Replay 图标单击即执行批量退款，风险过高。

### 建议流程

```text
IDLE
  -> SHOW_SUMMARY
  -> CONFIRMING
  -> SUBMITTING
  -> COMPLETED / REJECTED
```

### UI 要求

- Footer 左侧显示可退款队列或条目数量。
- 危险动作使用“退还队列”短文本加通用图标，不只显示 Replay。
- 确认区明确说明队列会被取消以及存储/背包满时可能掉落。
- 请求期间禁用重复点击，并保留槽页 bounds。
- 完成或拒绝后显示结果，不只依赖槽位突然变化。

## 8. Pattern Core 分页

- 上一页/下一页 Button 使用至少 `18x18` 命中区域。
- 首尾页显示 disabled 状态，单页时隐藏。
- 页码是可点击 Selector，可直接跳转。
- 页切换 handshake 期间在槽页上挂载固定 busy overlay，不移除或重排 64 个槽。
- busy overlay 显示“正在切换到第 N 页”。
- 鼠标滚轮/方向键切页只能在没有持有物品且焦点位于页控件时生效。

## 9. 多人状态

- 自动搭建和退款同步 host operation revision。
- 可选显示当前 busy actor，但不暴露不必要的玩家信息。
- 两名玩家基于不同 revision 提交时，后提交者收到明确 stale/retry 状态。
- 执行完成后广播结构/队列变化，所有打开菜单刷新。
- 服务端权限、generation、sequence、防重放和原子业务边界保持不变。
- 聚合样板页的 slot route、CPU 任务和当前合成详情分别同步独立 revision；一个区域 stale 不能让另一区域误写旧对象。
