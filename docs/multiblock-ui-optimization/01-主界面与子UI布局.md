### 入口规则

- 四个入口使用稳定的 `54x18` 命中区域，允许短标签加图标。
- 内部 key `main` 的玩家可见名称统一为“存储”；“主结构”只在结构状态和 Scene 语境中使用。
- 已关闭、已打开、当前置顶、pending、故障必须有不同状态类。
- 主点击行为是“打开或置顶”，不是 toggle 关闭。
- 关闭由子 UI 的关闭按钮或 Esc 完成。
- 点击故障摘要直接打开/置顶对应子 UI。

## 2. main / cpu / crafting 共用外框

三类业务子 UI 继续共用可拖动标题栏、关闭命令、独立 Scene 和观察 Dock，但不再共用一块只有状态行的 `84px` 侧栏。正常视口优先使用 `352x220` 的 data-workbench 布局，让业务页有可读宽度。

```text
352 x 220
┌──────────────────────────────────────────────────────────┐
│ 标题栏：CPU 子结构                                [关闭] │ 20
├────────────────────────────────┬─────────────────────────┤
│                                │ [业务页签]               │ 18
│                                ├─────────────────────────┤
│         Scene 196x162           │                         │
│                                │ 业务工作区 144x194       │
│ [选中][适配][复位] [全部 <3/8>] │                         │
├────────────────────────────────┤                         │
│ [参数][材料][检查] 当前上下文 Dock│                         │
└────────────────────────────────┴─────────────────────────┘
```

### 左侧固定区域

- `Scene` 始终存在，不因切换存储、任务、样板或合成详情而隐藏。
- Scene overlay 只保留选中方块、适应结构、相机复位和 compact layer control。
- Scene 下方使用一个 Dock；`参数` 一次只编辑一个 variant/tier/repeat/candidate，`材料` 使用水平 scroller。
- `检查` 只显示当前选中方块或故障位置的一行摘要；点击摘要打开 root-mounted 详情 popup。坐标、逻辑层、角色和候选不为每个业务窗口再复制一整页。

### 右侧业务工作区

每个窗口只挂载自己的业务页，具体布局见 [05-存储CPU与合成增强.md](05-存储CPU与合成增强.md)：

| 内部 key | 玩家可见职责 | 业务页 |
| --- | --- | --- |
| `main` | 存储 | `存储内容`、`结构状态` |
| `cpu` | CPU | `合成任务`、`结构状态` |
| `crafting` | 合成 | `样板槽位`、`合成详情`，顶层严格只有两页 |

`crafting` 的结构故障摘要进入共享 Scene Dock；退款等副作用动作只出现在与其对象相关的页内 action bar，不能挤出第三个顶层页。

### compact 布局

逻辑视口放不下 `352x220` 时按业务类型回落：

- 存储/CPU：`292x210`，Scene 列 `168px`，业务列 `112px`。
- 合成：`320x210`，Scene 列 `168px`，样板 workbench 保持 `144px`，确保 `8x8`、`18px` 槽池不缩放、不换列。

compact 文本使用静态截断加 tooltip。不能把业务列重新压成只容纳图标的 `84px`，不能缩小样板槽，也不能通过隐藏 Scene 获取空间。

## 3. auto_build 子 UI

自动搭建仍保留完整结构 Scene，但右侧不再同时堆放结构切换、开关、摘要、错误和确认。

```text
292 x 210
┌────────────────────────────────────────────────┐
│ 标题栏：自动搭建                       [关闭] │
├───────────────────────────────┬────────────────┤
│                               │ [设置][检查]    │
│                               ├────────────────┤
│                               │ 设置：目标结构  │
│         Scene                  │ main / cpu /... │
│                               │                │
│ [选中][适配]       [全部 <3/8>]│ 检查：材料/空间 │
│                               │ 结果与失败原因  │
├───────────────────────────────┼────────────────┤
│ [参数][材料] 当前参数 Dock     │ [开始搭建]      │
└───────────────────────────────┴────────────────┘
```

### 分区规则

- `设置` Tab：只选择当前单一搭建目标。
- tier/repeat/candidate 继续在 Scene 下方共享参数 Dock 中编辑。
- `检查` Tab：显示材料摘要、主结构前置条件、空间/权限/区块预检和服务端结果。
- 主按钮固定在右下角，不随 Tab 滚动。
- pending 时冻结目标和 recipe-affecting 参数，Scene 的相机和 layer 仍可查看。
- 关闭“不执行搭建”时不发送空请求；按钮文案直接写明当前目标。

## 4. 小视口与四窗并开

当逻辑视口接近 `320x240` 时，不继续用 7px 级联让四窗几乎完全重叠。

### compact 策略

- 默认只展示一个活动子 UI。
- 根界面 launcher 同时承担窗口切换器。
- 已打开但非活动窗口保持挂载状态和独立 Scene 生命周期，但暂不绘制或降低刷新频率。
- 提供“级联、恢复默认、关闭全部”三个 Modular UI 命令。
- 标题栏、关闭按钮和 Scene 永远优先保留。

宽视口继续允许自由拖动和多窗并排。

## 5. Pattern Core

Pattern Core 不需要结构 Scene，重点是让 8x8 样板区、分页、退款和玩家背包彼此分离。

### 常规纵向布局

```text
┌────────────────────────────┐
│ 标题                       │
│ 8 x 8 pattern grid         │
│                            │
├────────────────────────────┤
│ [上一页]  2 / 8  [下一页]  │
│                 [退还队列] │
├────────────────────────────┤
│ 玩家背包                   │
└────────────────────────────┘
```

### 低高度横向布局

```text
┌──────────────────────┬─────────────────────────┐
│ 标题                 │ 玩家背包                │
│ 8 x 8 pattern grid   │                         │
│                      │                         │
├──────────────────────┤                         │
│ [<] 2/8 [>] [退款]   │                         │
└──────────────────────┴─────────────────────────┘
```

两种布局复用同一组 `AeItemSlot` wrapper 和菜单协议，只改变 Modular UI 排版。
