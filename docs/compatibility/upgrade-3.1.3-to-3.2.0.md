# 3.1.3 到 3.2.0 的升级边界

本次清理只保留正式版本 `v3.1.3-1.21` 写出的数据到当前版本的直接升级路径，不再保留更早版本和开发中间版本的格式迁移。升级前应备份世界、玩家数据和客户端配置；此说明不承诺降级读取。

## 保留的直接升级路径

| 数据 | 3.1.3 格式 | 当前处理 |
| --- | --- | --- |
| 数位化磁盘 | `data_flow_cell_<tier>` | 物品注册别名指向 `digital_storage_cell_<tier>` |
| 便携式数位化磁盘 | `portable_data_flow_cell_<tier>` | 物品注册别名指向 `portable_digital_storage_cell_<tier>` |
| Trinity 存储核心和合并存储核心 | `me_digital_storage_core_<tier>g`、`me_digital_merged_storage_core_<tier>g` | 方块与物品注册别名均指向对应 `<tier>m` 核心，使用新容量 |
| Trinity 样板核心 | 容量状态版本 3，槽位容量 64 / 128 / 512 | 升级到版本 4，容量 72 / 144 / 576，保留原槽位内容 |
| Trinity 执行快照 | schema 5，长整型数量 | 读取并转换为 schema 6 的精确数量 |
| Trinity CPU 运行时 | schema 2，长整型容量 | 转换为 schema 3 的类型化容量，保留一基 worker 编号 |
| Trinity CPU 逻辑 | schema 2，普通库存表示 | 转换为 schema 3 的精确库存，保留正式版本的虚拟输出及无输出账本 |
| Trinity 执行任务 | schema 3 | 继续读取 schema 3 |
| Trinity 借用账本 | schema 1，长整型数量 | 转换为 schema 2 的精确数量 |
| Trinity 已用时间 | 正式版本的长整型基线 | 保留向当前时间统计的转换 |
| 样板编码客户端偏好 | JSON schema 3 | 升级到 schema 4，保留已有偏好与统计 |
| 拆解重组机 | 正式版本的单处理通道、进度及流体/自定义材料槽 | 保留向当前处理通道的恢复 |
| 数据陨石中心 | AE2 神秘方块 | 保留世界加载时转换为数据陨石中心的路径 |

两组磁盘各保留 `1k / 4k / 16k / 64k / 256k / 1m / 4m / 16m / 64m / 256m` 十档映射，共 20 个别名，均位于 `data_energistics` 命名空间。磁盘重命名发生在提交 `ad5833bfb`（#225），晚于正式 3.1.3；不能因旧别名类的历史注释而将这组映射归为 3.0 遗留。别名在物品注册事件前安装，只解析旧 ID，不再注册一套旧物品。

3.1.3 已经写出的当前格式继续直接读取，包括未改 ID 的数据流存储组件（`data_storage_component_<tier>`）和无限磁盘（`data_cell_infinity`）、塔绑定 schema 2、数字化资源键、光剑数据组件、玩偶名称、万能终端物品组件和部件 NBT，以及机器分类型输出面。万能终端的部件 NBT 不是过时格式，物品与部件之间的转换继续保留。

## 核心档位迁移规则

提交 `98af43462`（#222）在正式 3.1.3 之后将 Trinity 核心的 M/G 档体系改为 K/M 档，移除了两类核心的 `1g / 4g / 16g / 64g / 256g` 注册 ID：`me_digital_storage_core_<tier>` 和 `me_digital_merged_storage_core_<tier>`。

按已确认的迁移策略，旧 G 档迁入新档位，不保留旧 G 容量：`1G → 1M`、`4G → 4M`、`16G → 16M`、`64G → 64M`、`256G → 256M`。两类核心各有五个映射，分别安装到方块和物品注册表，共 20 个别名，覆盖已放置方块和保存的物品；这两类核心没有独立方块实体类型，因此不添加方块实体别名。

现有同名 M 档 ID 保持不变，不添加 `M → K` 别名：注册别名无法区分旧、新世界中的同名 ID，否则会把新版本创建的 M 档物品也错误降级。迁移使用目标核心的当前容量、类型上限和结构规则，不是容量等价替换；资源文件的 Git 相似度重命名不作为迁移依据。注册映射与编译检查不等同于真实旧世界升级验收，升级前仍须备份。

## 移除内容

- 更早的物品 ID 别名、NBT 自定义物品数据回退、旧玩偶状态和旧光剑颜色迁移。
- Trinity 执行/运行时/任务的更早 schema、零基 worker 编号和无版本容量状态。
- 3.2.0 开发期间集成充能器、异步处理工厂的过渡槽位布局。
- 旧服务端样板编码偏好到客户端 JSON 的迁移、迁移掩码和无效网络占位字段。
- 旧内部构造器、重载、别名，以及不携带完整结构绑定身份的回调桥。
- 拆解重组机和数字存储仓的旧合并输出面读取与旧字段镜像写出；正式版本已有的分类型字段继续读取。

这不是对所有包含 `legacy` 或 `compatibility` 字样的代码进行机械删除：普通 AE2 合成任务、当前第三方集成、有效的注册扩展能力和仍服务于正式 3.1.3 数据的转换继续保留。

## 网络与内部接口

样板编码协议删除了字段，因此网络握手版本从 5 改为 6。客户端与服务端必须使用匹配的构建；这不是修改模组版本或依赖版本，也不代表支持新旧客户端混连。

对外稳定 API 范围见[版本与稳定性](../api/versioning-and-stability.md)。内部类型不保留源码或二进制过渡桥。集合改为 fastutil 不改变 NBT 标签名称或数量编码：原始类型映射直接读取数值，只有需要区分缺失键与零值的业务边界才检查键是否存在。
