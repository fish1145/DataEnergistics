# Data Energistics「数位轨道武器」完整实施方案

## 1. 目标与最终玩法

- 新增一件由玩家持有、以不可变 `weaponId` 标识、由玩家 UUID 建立所有权索引的数位轨道武器。武器不以巨型实体常驻服务器世界；服务端只保存逻辑状态，客户端渲染轨道投影。
- 首版由玩家第一次放置“轨道控制台”创建武器记录；未来大型发射多方块结构仅替换“创建武器”的入口，存档、终端、信标、资源、攻击和渲染协议均不重做。首版不新增未接线的发射结构占位实现。
- 控制入口同时包含：
    - 轨道控制台方块；
    - 轨道控制终端物品；
    - 可选 Curios 专用饰品槽；
    - 未安装 Curios 时的主手/副手右键入口；
    - 装备或手持终端时可切换的 LDLib2 HUD。
- 所有本 Mod 新增的屏幕、弹窗、战术地图、状态面板和 HUD 均使用项目现有 LDLib2 2.2.35。原版 `AbstractContainerScreen` 只作为生命周期与 Menu 外壳，不承载可见控件。
- 武器拥有三套可并行运行的阵列，每种模式最多一个活动任务，因此单件武器最多同时执行三项攻击：
    1. 瞬时质量投射；
    2. 螺旋区域扫描光束；
    3. 轨道投射数位湮灭体。
- 已确认攻击不依赖操作者继续在线；服务器重启后从持久化阶段、工作游标和 escrow 恢复。目标区块允许按需生成，包括此前从未生成的区块。
- 攻击无视 FTB Chunks 及其他领地保护。领地信息只作为地图提示；世界边界、维度存在性、服务端配置和武器自身权限仍由服务端验证。
- 验收标准是完整玩法链路可用：星体能量生产 → AE 网络存储 → 信标充能 → UUID/角色访问 → 地图选点 → 费用预览 → 长按确认 → 公开预警 → 三形态执行 → 持久化恢复 → HUD、世界投影与第三方地图兼容。
- 术语统一锁定为“星体能量”；不再使用“星图数据”或“星象数据”作为该 AEKey 的显示名、代码名、资源 ID、配置字段或费用单位。
- “星体能量”虽然作为 `AEKey` 存储于 AE 网络，但它不是 AE 网络自身的 AE power。界面、配置和日志必须始终将“星体能量”与“AE 能量”作为两种独立资源显示。

## 2. 领域模型、资源与设施

### 2.1 星体能量仍属于 DigitalizationKeyType

- 新增单例 `CelestialEnergyKey`，显示名“星体能量”，资源标识使用 `data_energistics:celestial_energy`。
- 扩展现有 sealed `DigitalizationKey` permits 列表；不得创建新的 `AEKeyType`。
- 在 `DigitalizationKeyType` 中追加稳定 packet ID `2`；现有 `DataFlowKey=0`、`EchoKey=1` 永不重排，旧网络数据和旧存档继续兼容。
- 扩展资源 Codec、packet Codec、`DEAE2Keys.keys()`、AE 存储展示、数量格式化、图标/渲染、JEI/EMI/XEI/GuideME 展示、配方与语言资源。
- 星体能量直接作为通用 `AEKey` 进入普通 AE 网络、ME 存储和项目现有 `GenericStack`/Trinity 规划链路；不增加实体物品形式的“星体能量桶”或中间物品。
- 所有相关代码语义使用 `celestialEnergy`：
    - Java 类型：`CelestialEnergyKey`；
    - 注册/资源路径：`celestial_energy`；
    - 配置字段：`celestialEnergyCapacity`、`celestialEnergyUpkeepPerTick`、`celestialEnergyCost`；
    - UI、HUD、语言文件和配方说明：统一显示“星体能量”。
- 为 packet ID、资源 Codec 与旧 ID 兼容增加真实序列化测试。

### 2.2 重要类型与接口

| 类型/接口 | 责任 |
|---|---|
| `OrbitalWeaponRecord` | 一件武器的不可变 ID、所有者、角色、生命周期、储备、端点、锚点、冷却和三个活动攻击 |
| `OrbitalWeaponSavedData` | 保存全部武器及 `owner UUID -> weaponId`、授权反向索引；只在服务端主线程修改 |
| `OrbitalWeaponProvisioner` | 唯一建档契约；首版由语义明确的 `ConsoleWeaponProvisioner` 调用，未来发射多方块复用 |
| `OrbitalAttackMode` | `KINETIC`、`DIRECTED_ENERGY`、`DIGITAL_ANNIHILATION` |
| `OrbitalAccessRole` | `OPERATOR`、`OBSERVER`；所有者为记录的独立字段，不伪装成普通角色 |
| `TacticalMapAdapter` | 内置地图、JourneyMap、Xaero、FTB Chunks 的统一选点边界 |
| `OrbitalWeaponSettings` / `AstronomySettings` | 扩展现有只读配置 API 和配置快照，不让运行逻辑直接读取可变 schema |

- `OrbitalWeaponRecord` 使用不可变 `weaponId`，所有权转让只原子更新 owner index；控制台和信标保存 `weaponId`，不因转让而批量重写位置。
- 新包按领域和职责拆分为 `orbital/model`、`provisioning`、`storage`、`endpoint`、`astronomy`、`attack`、`networking`，客户端拆为 `ui`、`hud`、`map`、`render`、`compatibility`；不新增 `impl`、`manager`、`service`、`utils` 等兜底命名。
- 新领域包使用 `package-info.java` 的 JSpecify `@NullMarked`；所有跨模块接口完整说明线程、生命周期、空值、异常与副作用契约。

### 2.3 所有权与授权

- 第一次由玩家放置未绑定控制台时：
    - 玩家没有自己的武器：创建 `weaponId`，建立 owner index，并把控制台注册为首个上行端点；
    - 玩家已有自己的武器：控制台绑定现有 `weaponId`；
    - 玩家只被授权访问别人的武器：仍为自己创建独立武器，不会误绑定他人的记录。
- 控制终端物品不保存所有者 UUID，也不能靠丢弃物品转让武器。服务端根据当前使用者 UUID 返回其自有武器和被授权武器列表；LDLib2 顶栏默认打开上次使用且仍可访问的武器，并提供下拉切换。
- 权限固定为：
    - 所有者：管理授权、端点优先级、主锚点、转让、退役、瞄准、发射和紧急中止；
    - 操作员：瞄准、发射、撤销预警任务和紧急中止；
    - 观察员：只读界面与 HUD；
    - 三种角色都进入攻击确认时的实体伤害豁免 UUID 快照。
- 完整转让使用 60 秒、一次性、服务端签名的双方在线确认：
    - 接收者必须没有自己的武器；
    - 武器不得存在活动攻击、预留任务或重部署；
    - 新玩家成为所有者，旧所有者自动降为操作员；
    - 储备、端点、授权列表、主锚、冷却和统计全部保留。
- 受控退役仅在无活动攻击、无 escrow、储备均为零且全部端点已解绑时开放；通过 LDLib2 二次确认删除记录，不返还资源，之后原所有者可以重新建造。
- 名称只用于显示，所有授权、转让、豁免与索引以 UUID 为唯一依据。

### 2.4 控制台、统一上行信标与轨道生命周期

- 新增：
    - `orbital_control_console`：LDLib2 火控入口、AE 端点、首版武器建档入口；
    - `orbital_uplink_beacon`：AE 资源中继、目标维度解锁、世界投影锚点候选；
    - `orbital_control_terminal`：手持/Curios 火控入口。
- 控制台与上行信标都计入端点上限：默认每件武器 32 个、每维度 8 个，均自强加载自身一个区块；服务端配置可修改上限或完全禁用自加载。
- 端点被破坏、解绑或退役时立即释放票据；服务器启动时按 SavedData 恢复票据、加载对应区块并验证方块与 `weaponId`，不存在的陈旧记录会被移除。
- “在线端点”必须同时满足：方块有效、区块已加载、AE 网格存在且已供电。目标维度至少需要一个在线端点才能预览和确认攻击。
- 所有者可拖拽端点优先级。补充储备时每个 tick 只选择一个 AE 网格；当前网格无法提供任何所需资源时才故障转移到下一端点，不在同一事务中跨网格拼接扣费。
- 主投影锚定在所有者指定的在线信标。主信标失效时自动选择下一优先级端点；原信标恢复后不会自动跳回，避免反复重部署。
- 战斗中允许切换主锚：
    - 旧本体解构、新本体重组共 60 秒；
    - 已提交的目标端回声和攻击继续执行；
    - 重部署期间禁止确认新攻击，但可查看状态和紧急中止已有任务。
- 武器初次创建时为空储备、处于休眠。AE 能量与星体能量都达到容量 10% 后开始部署。
- 部署状态持续消耗储备；任一储备归零时立刻禁止新攻击，进入 10 分钟宽限期，随后主本体解构并进入休眠。已预付的攻击从各自 escrow 继续执行；再次补足两种容量的 10% 后重新部署，武器记录不删除。

### 2.5 两级天文观测设施

- 低级设施为单方块天文观测台：
    - 连接 AE 网格；
    - 中心上方必须可见天空；
    - 普通昼夜维度仅在 `dayTime % 24000` 的 13000–23000 tick 工作；
    - 晴天输出 8 星体能量/t，消耗 4000 AE/t；
    - 降雨输出 25%，雷暴停机；
    - 插入空间或 AE 能量不足时先模拟后停机，不吞能量、不虚空资源。
- 高级设施为可扩展干涉阵列：
    - 一个 5×5×3 核心基座；
    - 4–16 个 3×3 观测镜单元；
    - 镜单元位于核心水平 32 格内、高差不超过 4 格，通过最长 32 格的星能波导路径连接；
    - 每个镜面 3×3 天空孔径必须无遮挡，镜单元不能被多个核心共享；
    - LDLib2 结构预览展示最小四镜结构，并用可选槽位显示扩展位置与无效原因。
- 阵列产出采用递减收益：
    - 第 1–4 镜：每镜 40 星体能量/t；
    - 第 5–8 镜：每镜 30 星体能量/t；
    - 第 9–12 镜：每镜 20 星体能量/t；
    - 第 13–16 镜：每镜 10 星体能量/t；
    - 满阵列 400 星体能量/t。
- 阵列耗能为核心 25,000 AE/t，加每个有效镜 10,000 AE/t；天气倍率与低级设施相同。
- 维度规则由数据包标签决定是否可观测、是否永久处于观测窗口，再由服务端配置提供倍率：
    - 主世界类：1.0×；
    - 末地类：2.0×，默认永久可观测；
    - 下界类：0×；
    - 自定义维度可通过标签和配置覆盖，不在业务代码硬编码第三方维度 ID。

### 2.6 首版平衡默认值

| 项目 | 默认值 |
|---|---:|
| 星体能量轨道容量 | 500,000,000 |

- 所有费用、范围、冷却、产量、倍率、容量和调度预算进入现有双语服务端配置体系。
- 攻击确认时把几何、费用、配置 revision 和关键效果参数快照进任务；运行中的攻击不因配置热重载改变范围。配置改变后，旧预览令牌失效并要求重新预览。

## 3. LDLib2 火控、地图、HUD 与世界投影

### 3.1 LDLib2 火控界面

- 控制台和物品终端共享一个火控状态模型与同一棵 LDLib2 组件组合，仅访问来源不同：
    - 控制台 Menu 验证方块位置、距离和绑定武器；
    - 物品 Menu 验证主副手或 Curios 槽仍持有终端。
- 顶栏包含武器选择器、所有者、当前角色、主锚、部署状态和网络状态。
- 固定页面：
    1. 总览：AE 能量/星体能量储备、维护时间、主投影、三个模式与冷却；
    2. 战术地图：维度、X/Z、自动地表 Y、手动绝对 Y/相对偏移、模式范围；
    3. 攻击预览：区块数量、预计新生成区块、调度方块数、预计成本、预计执行时间；
    4. 上行网络：端点状态、维度、网格在线状态、拖拽优先级、主锚选择；
    5. 授权：所有者/操作员/观察员列表、转让；
    6. 安全：预警撤销、紧急中止、受控退役。
- 操作员看不到授权、转让和退役写操作；观察员的整个界面为只读。
- 目标 Y 默认由服务端读取最高运动阻挡表面；火控允许手动覆盖绝对 Y 或相对偏移，最终仍由服务端按目标维度构建高度验证。

### 3.2 内置战术地图

- 使用 LDLib2 实现无第三方依赖的战术地图。
- 服务端按视口请求返回战术瓦片，每瓦片覆盖 32×32 个区块，内容只包含：
    - 已生成区块标记；
    - 平均表面高度；
    - 生物群系色；
    - 区块线；
    - 上行信标、主锚与公开攻击标记；
    - 可选 FTB Chunks 领地提示。
- 地图浏览本身绝不生成新区块；未生成区域显示为“未知”，但仍允许输入坐标。只有攻击越过不可退款阶段后才进入受预算约束的区块生成。
- 地图瓦片按 revision 缓存，S2C 每批最多 64 项；每名玩家默认限速 4 次视口请求/秒，并使用客户端 LRU 缓存。
- 预览必须显示整个效果是否位于世界边界内；若完整攻击范围跨越世界边界，拒绝确认，而不是静默裁切效果。

### 3.3 JourneyMap、Xaero 与 FTB Chunks

- 三种地图全部是可选兼容；缺少任意 Mod 时不影响启动、内置地图、服务端或其他地图适配。
- 双向工作流统一为：
    1. 在 LDLib2 火控中选择地图提供者并进入带会话令牌的选点模式；
    2. 在地图点击/右键坐标；
    3. 返回 LDLib2 火控预览；
    4. 客户端只提交维度与坐标，服务端重新验证全部权限、范围和费用；
    5. 地图自身右键菜单也可直接创建同样的火控预览会话。
- JourneyMap 使用正式 v2 插件和全屏地图事件，不使用 Mixin；其官方 1.21.1 文档提供插件注册方式，官方示例包含全屏点击、弹出菜单与工具栏事件：[JourneyMap API 接入文档](https://github.com/TeamJM/journeymap-api/blob/1.21.1_2.0.0/docs/howto.md)、[官方事件示例](https://github.com/TeamJM/journeymap-api/blob/1.21.1_2.0.0/common/src/testmod/java/example/mod/client/plugin/ClientEventListener.java)。
- Xaero World Map 使用 `compileOnly` 的 XaeroLib/World Map 类型和仅客户端条件 Mixin/accessor，不使用反射。Create 的 1.21.1 分支已采用 XaeroLib 1.0.42、World Map 文件 7401095 及独立兼容 Mixin，可作为版本与隔离方式基线：[Create 1.21.1 可选依赖配置](https://github.com/Creators-of-Create/Create/blob/mc1.21.1/dev/build.gradle)、[Xaero 条件兼容 Mixin 清单](https://github.com/Creators-of-Create/Create/blob/mc1.21.1/dev/src/main/resources/create.mixins.json)。
- FTB Chunks 使用 2101.1.x 的 `compileOnly` 客户端适配，对大地图 Screen 建立条件 accessor 和坐标转换；FTB 官方仓库确认该 Mod 同时提供全屏地图与区块领地功能，2101.1 系列对应 Minecraft 1.21.1：[FTB Chunks 官方仓库](https://github.com/FTBTeam/FTB-Chunks)、[官方 2101.1.x 变更记录](https://github.com/FTBTeam/FTB-Chunks/blob/main/CHANGELOG.md)。
- Xaero/FTB Mixin 配置由 Mod 是否加载决定，注入 `require=0`，失败时只记录一次明确日志并停用对应适配，绝不影响内置地图。
- FTB Chunks 领地只显示在地图预览中；攻击逻辑明确不调用领地编辑许可，也不因领地归属拒绝或裁切。
- 构建版本目录新增 JourneyMap API 2.0.0、XaeroLib 1.0.42、Xaero World Map 7401095、FTB Chunks 2101.1.9 的可选依赖；`neoforge.mods.toml` 全部声明为客户端 optional。

### 3.4 HUD 与 Curios

- 新增一个 LDLib2 只读 HUD 根，通过客户端 GUI overlay 生命周期挂载；不得另写一套直接 `GuiGraphics` 拼文字的 HUD。
- 显示条件：
    - 终端位于 Curios 专用槽，或主手/副手；
    - 玩家至少能访问一件武器；
    - 玩家可用快捷键隐藏/显示。
- 默认精简显示：选中武器、角色、部署状态、AE 能量/星体能量储备、可用端点、三模式冷却。
- 存在预警、攻击、故障或储备耗尽时自动展开对应模式卡片；观察员能看但不能点击写操作。
- Curios 保持可选依赖；新增独立轨道终端槽 JSON。无 Curios 环境中，手持右键与快捷键仍打开完全相同的 LDLib2 火控。

### 3.5 512 格轨道构装体

- 主本体采用“AE 数位构装体”风格：半实体分段外壳、AE 网格光路、体素解码、线框重组和数据裂隙。
- 默认总长度约 512 格，由共享数位核心和三套独立火力阵列组成：
    - 双轨质量投射器；
    - 同心环定向能阵列；
    - 数位湮灭体投射架。
- 逻辑武器只有一份；世界表现分为：
    - 主投影：部署后始终位于主信标 X/Z、维度最大构建高度上方 320 格；
    - 目标端火力回声：每项预警/攻击在目标上空投射对应阵列与半透明核心回声；
    - 最多三个目标端回声，可处于不同维度。
- 主投影对主锚维度全员可见；目标回声和攻击效果对目标维度全员可见。玩家进维度、重登或迟到时立即收到当前阶段快照。
- 不创建 512 格实体、碰撞箱或追踪实体。主投影、阵列、光束、冲击环均由客户端 level renderer 和维度作用域缓存绘制；只有数位湮灭体的实际下降载荷使用小型实体。
- 使用三级 LOD：
    - 1024 格内：完整分段模型、骨架运动、粒子和局部光路；
    - 1024–4096 格：低面数模型与合并光路；
    - 4096 格外：天幕 impostor、目标方向光柱和低频动画。
- 每帧执行视锥裁剪、按 RenderType 合批、限制全精度投影数量；动画由攻击 UUID、服务端开始时间和随机种子确定，不逐 tick 同步骨骼。
- 三形态动画：
    - 动能：质量轨道闭合、瞬时垂直残影、冲击环；
    - 定向能：能量环展开，光束位置严格跟随服务端螺旋工作游标；
    - 湮灭体：投射架解码实体、数位相位下降、实体化后切换现有引信/膨胀视觉。

## 4. 攻击、网络、持久化与性能

### 4.1 服务端攻击流程

统一状态机：

`TARGET_PREVIEW → RESERVED_WARNING → COMMITTED → DELIVERY/WORKING → COMPLETED/ABORTED/FAULTED → COOLDOWN`

- 预览会话含随机 nonce、玩家 UUID、武器 ID、配置 revision、状态 revision、目标维度、几何和 30 秒有效期。
- 长按 60 tick 后，服务端再次验证：
    - 使用者角色；
    - 控制台距离或终端物品仍存在；
    - 对应模式没有活动任务且冷却结束；
    - 武器不在休眠或重部署；
    - 目标维度仍有在线上行端点；
    - 世界边界、构建高度、半径和全服任务上限；
    - AE 能量与星体能量轨道储备余额。
- 验证成功后从武器储备原子划入该模式 escrow，并进入 300 tick 公开预警；此时目标端火力回声显形。
- 预警期内所有者或操作员可以撤销，escrow 全额回到轨道储备。
- 300 tick 后任务提交且不再退款。所有者或操作员仍可紧急中止：
    - 立即停止未执行的后续破坏；
    - 已造成效果不回滚；
    - 释放攻击区块票据；
    - escrow 全部视为消耗。
- 每种模式拥有独立任务槽和冷却，允许三个模式并行，但同一模式不排队。
- 攻击确认时复制所有者、操作员和观察员 UUID 为本次豁免快照。之后修改授权不改变已提交攻击的豁免集合。
- 创造、旁观及权限等级 2 的管理员继续全局豁免。
- 玩家下线不取消任务；服务器保存任务阶段、时间、几何、配置快照、escrow、豁免集合、生成游标和方块工作游标。

### 4.2 三种形态的确定行为

| 模式 | 几何与效果 | 默认费用 | 冷却 |
|---|---|---:|---:|
| 瞬时质量投射 | 半径 8 垂直柱，从维度最高构建高度清至目标 Y 下 192；命中点追加半径 24、深 16 的浅陨坑；半径 64 冲击环造成 500 点伤害与强击退 | 5,000,000 星体能量 + 5,000,000,000 AE | 无冷却 |
| 螺旋区域扫描 | 半径 16–256、步进 16；深度档 32/128/512/贯穿；从世界顶端沿螺旋覆盖圆盘，清至 `targetY-depth`，实体每次被光束覆盖时受到 500 点伤害 | 基础 2,000,000 星体能量 + 2,000,000,000 AE；再按每个调度坐标 4 星体能量 + 2,000 AE | 完成后 100 tick（5 秒） |
| 数位湮灭体 | 轨道载荷下降 80 tick，穿越方块且不提前破坏；抵达指定 Y 后实体化，进入现有 80 tick 引信；随后按现有数位湮灭体球形配置扩张 | 80,000,000 星体能量 + 80,000,000,000 AE | 完成后 72,000 tick |

- 三种模式移除方块时均抑制掉落；默认允许移除不可破坏方块，并明确绕过领地保护。管理员可全局禁用某种模式，但不加入按领地裁切的隐式行为。
- 动能的视觉和实体伤害在命中 tick 瞬时发生；地形变更仍通过预算工作器在随后少量 tick 内完成，避免单 tick 峰值。
- 光束费用按整个几何调度坐标数计算，包括空气，不按实际非空气数量退款或折扣；因此未知区块、地下空洞和已清理区域不能降低费用。
- 光束的服务端螺旋枚举必须保证每个圆盘列恰好处理一次；客户端只插值服务端游标，不独立推算命中。
- 新增小型 `OrbitalAnnihilatorProjectileEntity`：
    - 从目标维度最大构建高度上方 256 格开始；
    - 80 tick 内按目标 Y 插值下降；
    - 相位阶段无碰撞、不受推力、不跨传送门；
    - 抵达后生成现有 `DataNukePrimedEntity`，写入 80 tick 引信、原点和豁免 UUID。
- 抽取现有湮灭逻辑为可保存、可预算的 `DigitalAnnihilationWork`，供手动点燃和轨道投射共同使用：
    - 球形范围、无掉落、实体吞噬与现有最大半径配置不变；
    - `workIntervalTicks` 成为完成上一层球壳后的最小间隔；
    - 手动点燃的湮灭体没有额外授权豁免，保持原行为；
    - 活跃湮灭区增加玩家/实体进入检查，防止实体在已处理球壳内部重新进入后存活。

### 4.3 自动生成与受预算强加载

- 允许攻击完整生成此前不存在的目标区块；地图预览必须突出显示预计新增区块数和可能的长时间执行提示。
- 禁止在攻击循环中调用同步 `getChunk(..., true)`；所有区块通过未来值请求，准备完成后才进入方块工作队列。
- 默认调度上限：
    - 每个攻击任务同时持有最多 8 个工作区块票据；
    - 全服攻击票据最多 64 个；
    - 每维度同时生成最多 2 个新区块，全服最多 8 个；
    - 每任务最多修改 8192 个方块/t；
    - 全服攻击合计最多修改 32768 个方块/t；
    - 全服最多 32 个已提交工作任务；达到上限时在扣费前拒绝确认。
- 使用公平轮转调度三个模式和不同玩家的任务，不能让 2048 半径湮灭体长期饿死其他任务。
- 每个区块/section 完成后更新持久化游标并释放不再需要的票据；每次相位变化和固定进度间隔标记 SavedData dirty。
- 区块生成、方块工作和客户端特效速度可以因服务器预算变慢，但几何结果不得跳过或改变。
- 2048 半径湮灭体可能生成和处理数万区块；允许任务跨多次服务器运行持续完成，不通过提高单 tick 工作量强行追赶。

### 4.4 网络与同步

- 将现有 payload registrar 协议版本由 `"5"` 升为 `"6"`，明确拒绝新旧客户端混连。
- C2S 只发送意图：
    - 打开/切换武器；
    - 请求地图瓦片；
    - 请求预览；
    - 长按确认；
    - 预警撤销/紧急中止；
    - 端点排序/主锚切换；
    - 角色修改、转让与退役。
- 客户端不得发送或决定费用、伤害、命中实体、储备余额、豁免集合、冷却和任务阶段。
- 私有 `OrbitalStateSnapshot` 只同步给有访问权的玩家；公共 `AttackVisualSnapshot` 只含渲染需要的攻击 ID、模式、维度、目标、阶段时间、几何摘要、随机种子和公开进度，不泄露授权列表或储备。
- 状态快照包含单调 revision；乱序或旧快照丢弃。Map payload 继续遵循项目现有最多 64 项批处理范式。
- 玩家登录、切换维度、武器选择变化和攻击阶段变化时发送全量基线，随后只发送差量；HUD 不轮询服务器。
- 所有 payload handler 使用 `enqueueWork` 回到正确线程，并对目标坐标、枚举、半径、深度、UUID、批次数量、字符串长度和会话过期进行边界验证。
- 对预览、地图瓦片、确认和授权修改分别限速，拒绝重复 nonce 和重复确认。

### 4.5 故障与管理员恢复

- 预留前失败：不扣资源。
- 预警期撤销：全额返还到轨道储备，不尝试写回原 AE 网格。
- 提交后缺区块或等待预算：进入 `WAITING_FOR_CHUNK/BUDGET`，保持任务，不退款。
- 工作器内部异常：
    - 顶层任务边界捕获；
    - 记录一次包含武器 ID、攻击 ID、模式、维度、目标和游标的错误；
    - 任务进入 `FAULTED`，释放票据并保留诊断游标；
    - 不在 tick 中无限重试或刷日志。
- 增加管理员命令用于 inspect、retry、abort、对 `FAULTED` 任务显式 refund、修复 owner index 和移除陈旧端点。玩家不能利用管理员恢复接口取得按进度退款。
- 服务器停止前正常保存；启动后先恢复 SavedData 和端点票据，再恢复攻击调度，最后向在线客户端同步视觉。
- 所有运行时数值在 NBT/Codec 入口校验有限、非负和范围；非法内部状态 Fail Fast，旧存档在读取边界规范化一次，不在每层重复兜底。
