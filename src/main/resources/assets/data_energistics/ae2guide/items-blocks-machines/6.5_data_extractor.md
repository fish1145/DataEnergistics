> Data Extractor extracts hidden rules from massive information streams and converts raw materials into structured data.
>
The logic is a bit complicated; I suggest referring to what is said below. ⚠  
> The main purpose is to attack targets with high-value sword weapons to generate Data Flow, and to use Data Carrier to record corresponding items or creatures and create corresponding Data Carrier

# Upgrade

<Row>
    <ItemLink id="ae2:capacity_card"/>
    <ItemImage id="ae2:capacity_card" />
</Row>
Capacity Cards:  
Simultaneously increase the upper limit of the target and the scope of work.

Target Upper Limit Formula: ⚠  
> Target cap = base target cap + capacity card count × additional target per card

In the default configuration: ⚠  
> Target cap = 20 + capacity cards × 5

Range formula: ⚠
> - Horizontal expansion: each capacity card increases by 1 square on each side
> - Vertical height = 3 + capacity card quantity × 2

By default: ⚠
> - 0 capacity cards: horizontal foundation radius 1, vertical height 3
> - For every extra card: +1 square per side horizontally, +2 squares vertically

---

<Row>
    <ItemLink id="ae2:speed_card"/>
    <ItemImage id="ae2:speed_card" />
</Row>
Speed Cards shorten the working cycle.

Interval formula: ⚠  
> Final working time (seconds) = Base working time - (number of Speed Cards × 1)

Default base working time is 5 seconds:
- 0 sheets: Works every 5 seconds
- 1 piece: work every 4 seconds
- 2 sheets: work every 3 seconds
- 3 sheets: work every 2 seconds
- 4 sheets or more: work every 1 second

---

<Row>
    <ItemLink id="ae2:energy_card"/>
    <ItemImage id="ae2:energy_card" />
</Row>
Energy Cards increase the base Data Flow generated each round and enhance the internal AE energy storage buffer.

Basic Data Flow formula: ⚠  
> Base Data Flow per round = base value + number of energy cards × 200 + damage dealt this round × additional Data Flow per damage point

In the default configuration: ⚠  
> Base Data Flow per round = 100 + number of energy cards × 200 + damage dealt × 20

Internal AE buffer formula: ⚠  
> Internal buffer = 1600 + energy card count × 100

---

# Multi-objective multiplier
When a single task affects multiple goals, the base Data Flow is multiplied by a target multiplier.

Formula: ⚠  
> Final Data Flow = base Data Flow × per round (1 + max(0, number of targets - 1) × additional target multiplier)

Default extra target multiplier is 0.25:
- 1 goal: × 1.00
- 2 goals: × 1.25
- 3 goals: × 1.50
- 4 goals: × 1.75

These base values can continue to be adjusted in the configuration file.

# Data Carrier
<ItemImage id="data_energistics:data_carrier"  scale="6" />

Data Extractor will use blank spaces  
<Row>
    <ItemLink id="data_energistics:data_carrier"/>
    <ItemImage id="data_energistics:data_carrier" />
</Row>
Carrier as the foundational medium.  
After the recording is completed, it will automatically be converted into the corresponding finished Data Carrier. ⚠

Basic Rules:
- Place the blank Data Carrier into the upper left main slot
- A blank carrier can only record one category at a time
- Once biological data is recorded, ore or crop data cannot be mixed in
- Once you start recording ore data, you can't mix in biological or crop data
- Once crop data is recorded, biological or ore data cannot be mixed in
- When the progress reaches the required level, the blank carrier will become the corresponding finished carrier

# Biological Data Carrier
<Row>
    <ItemLink id="data_energistics:mob_data_carrier"/>
    <ItemImage id="data_energistics:mob_data_carrier" />
</Row>

Recording Process:
- Place the blank Data Carrier into the main slot
- The sword slot can hold weapons; If empty, the machine deals base magic damage
- The extractor periodically damages living targets within its range
- On the first successful record, the carrier locks onto the current creature type being damaged
- Only effective damage dealt to the same creature will continue to accumulate progress

Progress sources:
- Progress directly follows the actual damage dealt to the target creature
- After meeting the requirements, the blank carrier will become <ItemImage id="data_energistics:mob_data_carrier" />

Features:
- Suitable for locking onto a specific creature
- Can later be placed in Data Mimetic Field to simulate the creature's drops

# Ore Data Carrier
<Row>
    <ItemLink id="data_energistics:ore_data_carrier"/>
    <ItemImage id="data_energistics:ore_data_carrier" />
</Row>

Recording Process:
- Place the blank Data Carrier into the main slot
- Place ore in the mineral tank or configure other valid mineral inputs that are allowed
- On the first recording, the carrier locks onto the mineral target represented by the current input
- Only after input of the same target will progress further

Progress sources:
- Default count of normal ores is '1:1'
- By default, coarse ore counts as '0.5:1'
- If an ore row exists in `carrierRules`, it takes precedence:
  - `recorded_item`
  - `progress_per_item`
  - `required_amount`

Completion Requirements:
- After the requirements are met, the blank carrier will become <ItemImage id="data_energistics:ore_data_carrier" />

# Crop Data Carrier
<Row>
    <ItemLink id="data_energistics:crop_data_carrier"/>
    <ItemImage id="data_energistics:crop_data_carrier" />
</Row>

Recording Process:
- Place the blank Data Carrier into the main slot
- Put crops, seedlings, fungi, flowers, bamboo, sugarcane, cacti, or other inputs allowed in the trough
- On the first recording, the carrier locks onto the crop target represented by the current input
- Only after matching the target input will progress progress

Progress Source:
- The default standard crop input counts as '1:1'
- Partial mapping inputs can be configured through conversion, for example:
  - Wheat seeds -> Wheat, '0.5'
  - Beet seeds - > Beets, '0.5'
  - Watermelon seeds / Watermelon slices - > Watermelon, '0.5'
  - Pumpkin seeds - > Pumpkin, '0.5'
- If a crop row exists in `carrierRules`, it takes precedence:
  - `recorded_item`
  - `progress_per_item`
  - `required_amount`

Effective Objectives:
- Conventional crops
- Lower Border Warts
- Seedlings and mangrove viviparous seedlings
- Mushrooms and fungi
- Sweet berries
- Watermelon and pumpkin
- Bamboo, sugarcane, cacti
- Various flowers
- Any additional input you have configured

Completion Requirements:
- After meeting the requirements, the blank vector will become <ItemImage id="data_energistics:crop_data_carrier" />

# Configuration rules
Data Extractor share an independent rule table with Data Mimetic Field:

`config/data_energistics/data_extractor_rules.yaml`

---

Where:
- `carrierRules` controls what is allowed in each extractor slot, what data is recorded, how much progress each item provides, and total demand
- `outputRules` controls what the finished product will produce in Data Carrier Data Mimetic Field
- Values at the same index across the arrays form one rule row; the YAML comments describe each column

New rule files are created with the built-in default rows. Existing arrays are used as configured; clearing them does not load an older configuration or restore a separate fallback table.
If there is no corresponding `outputRules` entry, Data Mimetic Field will revert to the default loot table or hardcoded drop logic.
