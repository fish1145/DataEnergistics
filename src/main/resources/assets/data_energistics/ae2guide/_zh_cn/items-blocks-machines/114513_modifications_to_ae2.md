# 对 AE2 的改动

Data Energistics 在保留 AE2 原有网络、存储和自动合成接口的基础上，扩展了合成规划、处理样板、样板供应器、存储键和终端界面。下面只列出会影响实际使用方式的行为变化。

## 相比 AE2 原版的合成计划优化

将AE原生规划器转接为 Trinity 规划器；当请求由 Trinity 规划器接管时，主要改进集中在计划的搜索范围、循环处理、结果复用和计算调度：

- **只编译目标可达的配方图**：从请求目标反向收集可达子图，去重并展开输入绑定变体，再编译成不可变结构。不会为了一个请求遍历与目标无关的整张配方网络。
- **用强连通分量拆分循环**：使用 Tarjan 分析将配方图划分为循环分量和无环部分，并构建压缩后的 DAG。无环部分使用反向需求传播，循环只在所属分量内求解，避免把循环依赖反复展开成错误的线性链。
- **循环使用精确求解和计划压缩**：确定性循环通过净变化和前缀缺口直接计算启动材料与重复次数；复杂循环使用非负整数优化寻找更少的配方执行次数，并用 `BigInteger` 精确复核结果。重复轮次以压缩调度保存，不为每一轮生成冗余计划节点。
- **全局需求聚合和路线选择**：跨多个产出配方、边界材料和循环种子统一聚合需求，在共享的搜索预算内回溯选择可行路线，而不是只沿着单条局部路径生成计划。
- **分层缓存和并发请求合并**：可达图、配方变体、目标结构、路线提示和相同请求的进行中计算都可以复用。同一 Grid、图版本和请求语义的并发计算会合并等待；图版本变化或 Grid 卸载时会失效或取消旧结果，避免使用过期计划。
- **异步且有界的计算调度**：初始计划和 Trinity CPU 的剩余工作重规划使用独立的有界工作线程和队列，不把长时间搜索压在游戏主线程上。达到最优性证明时间上限时，只要已有结果通过可行性验证，就保留该可执行计划；超过搜索边界的请求会给出明确诊断。

因此，这里的“计算加速”指合成计划的搜索、复用和重规划效率提升。对于不需要 Trinity 特性的普通无环请求，系统仍保留 AE2 原生路径作为回退。

## 循环下单

AE2 原生合成规划更适合无环依赖。Data Energistics 为 Trinity 合成 CPU 增加了循环配方规划与执行，使产物会回到前置配方、多个配方互相提供输入，或同一批材料需要在环内重复利用的配方链可以被识别和下单。

例如：

1. 配方 A 消耗 X 并产出 Y；
2. 配方 B 消耗 Y，重新产出 X，并额外产出目标 Z；
3. 系统计算启动循环所需的最少 X、每轮净产出和需要重复的轮数；
4. 下单后按已经证明安全的阶段顺序执行 A、B，并重复完整循环，直到满足 Z 的请求量。

循环规划会计算以下内容：

- **启动种子**：开始第一轮循环前必须已经存在的最少材料；
- **环内复用**：同一轮或后续轮次会继续使用的中间产物；
- **净消耗与净产出**：完整执行一轮后，每种材料的最终变化；
- **循环次数**：满足最终请求所需的完整重复次数；
- **执行顺序**：避免先执行尚未获得输入的阶段。

### 确认界面

当计划包含循环时，合成确认界面会使用不同颜色标记各个环。悬停材料可以查看它在当前环中的作用、库存使用量、启动种子、净变化、配方执行数和循环次数。

同一种材料同时属于多个环时，可以使用“上一个 Trinity 环”和“下一个 Trinity 环”按键切换悬停详情。合成计划树也会保留完整环关系，展开或折叠节点时不会把一个循环拆成错误的单向链。

### 使用限制

- 循环计划只能提交给可用的 **Trinity 合成 CPU**；普通 AE2 CPU 不执行这种压缩循环计划。
- 缺少启动种子时，确认界面会显示精确缺少量，任务不会通过无限重试掩盖材料不足。
- 没有净产出、无法生成目标物或超过配置复杂度上限的循环会被拒绝。
- 执行中的循环按可用输入和目标容量分批发配，不会一次性把无法接收的全部材料推给机器。
- 服务器重启后，未完成的循环次数、阶段进度和等待状态会从持久化数据中恢复。

## 处理样板忽略 NBT

处理样板的第一个物品输出可以在两种匹配方式之间切换：

- **精确匹配数据组件**：运行时产物必须与样板声明的完整物品键一致；
- **按注册物品匹配**：只要求物品注册 ID 相同，忽略数据组件差异。

Minecraft 1.20.5 之后，物品的名称、附魔、耐久、容器内容和其他旧 NBT 数据大多由 Data Components 表示。因此界面中的“忽略数据组件”就是通常所说的“忽略 NBT”。

### 设置方法

1. 在 AE2 样板编码终端切换到处理样板模式；
2. 设置至少一个物品输出；
3. 打开第一个输出的数量设置窗口；
4. 使用左侧新增的匹配按钮，在“精确匹配数据组件”和“按注册物品匹配（忽略数据组件）”之间切换；
5. 编码或重新编码样板，匹配方式会写入这张处理样板。

该选项只适用于处理样板的**第一个物品输出**。没有物品输出、合成样板、流体输出和其他 AE 通用资源键不能使用这个开关。

### 实际行为

启用后，假设样板声明输出一把普通铁剑，机器实际返回同一注册物品的带名称、附魔或不同耐久铁剑，Trinity CPU 仍可以把它认作这次声明的输出。

但系统不会删除或覆盖真实产物的数据组件：

- 返回物品仍保留机器实际生成的完整名称、附魔、耐久和其他组件；
- 忽略组件只用于判断某个运行时产物能否满足这次待收取的输出声明；
- 普通中间产物只允许在产生它的同一合成任务中按同物品规则继续使用；
- 最终请求产物会保持隔离并交付，不会被后续步骤当作中间材料重新消耗；
- 同一任务中存在互相冲突或无法唯一归属的动态输出时，系统会拒绝不安全的发配。

使用忽略数据组件输出的请求必须由可用的 Trinity 合成 CPU 执行。普通 AE2 CPU 不理解这种动态产物匹配，确认界面会提示需要 Trinity CPU。

## 编码后上传样板

Data Energistics 为 AE2 样板编码终端和通用样板编码终端增加了编码后直接上传样板的流程。终端设置中的 **启用 Data Energistics 上传** 默认开启；关闭后，编码按钮恢复 AE2 原生行为，不打开上传面板。

### 上传步骤

1. 在样板编码终端中配置配方并编码样板；
2. 编码成功后打开上传面板，查看当前网络中可用的样板供应器分组；
3. 使用搜索框筛选供应器；
4. 左键供应器分组或具体供应器叶节点，将编码样板写入可用的供应器槽位；
5. 右键或使用打开按键可以进入对应供应器界面，检查槽位、名称和具体物理位置。

上传面板会显示供应器已写入样板数、总槽位、方块/部件/外部供应器类型，以及可识别的配方类别和工作站。处理样板会优先显示与当前配方类别和工作站上下文精确匹配的供应器；选中一个分组后，系统会按当前可用的物理叶节点依次尝试提交，直到样板数量全部写入或没有可用目标。

### 工作站与机器模式校验

- 编码样板会保留配方类别、配方 ID 和工作站上下文；
- 普通处理样板会在上传前解析其配方来源，并根据当前网络中暴露的工作站筛选供应器；
- 数据充压一体机注册为样板上传工作站。上传充能、压粉、增产、压印或水晶生长样板时，机器必须切换到对应模式；
- 当前模式不匹配、一个样板同时匹配多个模式、配方 ID 已失效或无法解析时，上传会被拒绝，编码器中的样板不会被消耗；
- 工作站检查在供应器库存变更前执行，机器状态变化和样板写入由一次可回退的事务协调。

### 重复与失败保护

- 如果目标供应器组已经存在完全相同的编码样板，系统不会再次插入；编码样板会被清空并返还为空白样板，避免重复占用槽位；
- 目标离线、没有可用槽位或没有匹配工作站时，样板保留在编码器中，并显示失败原因；
- 供应器实际库存发生变化但无法确认增量时，系统不会继续消耗新的编码样板，而是保留当前样板并提示检查目标；
- 上传成功后会记录实际接收样板的供应器、维度、坐标和时间，便于定位刚刚写入的目标；
- 同一网络中的普通 AE2 供应器、数据能源供应器和 Trinity 聚合供应器可以通过各自声明的上传目标参与流程，未声明兼容关系的目标不会被强行写入。

## 样板供应器批量投递

普通 AE2 样板供应器向外部库存发送处理输入时，Data Energistics 会先模拟目标容量，再把多个相同逻辑合成合并为一次可接收的批量投递。

- 投递数量不会超过当前请求数量；
- 不会超过目标库存实际可接受的容量；
- 物品、流体和 AE 通用资源键都会按精确数量缩放；
- 任一输入无法完整接收时，不会提交半份逻辑配方；
- 专用合成机器、结果锁定、脉冲锁定等不能安全批量化的路径仍沿用 AE2 的单次投递行为。

这项改动减少了大量重复的单份推送，也让 Trinity CPU 可以依据机器和输入缓存的真实容量决定每一批下单数量。

## 目标轮转分配

当同一个样板供应器有多个可用输出方向时，会继续使用 AE2 的轮转游标选择目标。Data Energistics 的批量投递会保留这个行为：

1. 从当前轮转位置开始检查各个方向；
2. 跳过离线、锁定、阻挡或容量不足的目标；
3. 向第一个能够完整接收本批输入的目标投递；
4. 只有投递成功后才推进轮转位置；
5. 下一批从后续目标开始检查。

因此多个相邻机器能够循环接收订单；失败目标不会吞掉轮转进度，也不会因为某一面暂时堵塞而永久饿死其他可用目标。

## Trinity 接入 AE2

三位一体数位化核心通过信息交换仓向 AE2 网络发布三类服务：

- 大容量 AE 通用存储；
- 一个或多个虚拟合成 CPU；
- 由样板核心聚合的合成样板供应器。

这些能力仍使用 AE2 的网络、频道、存储优先级、样板优先级和合成任务接口。结构失效、信息交换仓离线或租约切换时，服务会从 AE2 网络撤回，避免同一个 Trinity 主机通过多个仓重复发布存储、CPU 或样板。

## 样板编码与配方来源

Data Energistics 还扩展了 AE2 样板编码流程：

- JEI/EMI 配方转移会保留配方来源和机器工作站信息；
- 数据充压一体机等多模式机器在上传样板时会校验当前模式；
- Trinity 会为 AE2 合成、切石和锻造样板保存稳定配方 ID；
- 配方重载后，无法重新解析或出现歧义的样板不会被静默解释为另一份配方；
- 样板管理支持聚合浏览、搜索、优先级和尽力迁移。

---

## 存储与通用资源键

为了让数据流、数位化、显化二进制和其他非物品/非流体资源参与 AE 网络，Data Energistics 扩展了 AE 通用资源键在存储、配置槽、输入输出总线和合成发配中的处理。

这些资源可能以 Wrapped Generic Stack 的物品形式显示或搬运，但其真实身份仍是原始 AEKey 和精确数量。迁移、导出和自动化逻辑会尽量保留真实键，不应把包裹物当作普通物品配方材料处理。

---

## 兼容与回退

- 普通无环合成在不需要 Trinity 特性的情况下仍可交给 AE2 原生规划器和普通 CPU。
- Trinity 规划无法接管但 AE2 可以正常处理的请求，会回退到 AE2 路径并在确认界面标明来源。
- 循环下单、忽略数据组件的动态输出等 Trinity 专用计划不会错误回退到普通 AE2 CPU。
- 第三方样板供应器和工作站只有在兼容适配成功加载时才启用扩展行为；未安装对应模组不会阻止 AE2 或 Data Energistics 启动。
