# 订单包裹

<Row>
  <ItemImage id="data_energistics:order_package" scale="6" />
    <ItemImage id="data_energistics:order_package" />
</Row>

订单包裹是一种用于 **虚拟下单** 的特殊物品。它本身不是实际的物品、流体或数据资源，而是携带一个“目标 AEKey”的订单输出。将带有目标的订单包裹写入样板后，合成系统会把它解释为对该目标资源发起一次合成请求。

## 设置订单目标

1. 手持订单包裹右键打开订单包裹界面；
2. 将要下单的物品、流体或其他 AE 通用资源拖入中间的目标槽；
3. 目标槽只记录资源类型，不记录数量；
4. 关闭界面后，目标会保存到订单包裹的数据组件中；
5. 再次打开订单包裹可以查看或替换当前目标。

目标槽支持 JEI 和 EMI 的拖放操作，也支持 AE2 能识别的通用资源。对于物品和流体，界面会保存对应的 AEKey；对于数据流、数位化资源等通用资源，会保存其原始通用资源键，而不是把它们转换成普通物品。

右键目标槽可以清除目标。未设置目标的订单包裹仍然可以携带和存储，但不能作为有效的虚拟订单输出使用。

## 在样板中使用

在 AE2 样板编码终端中，将带目标的订单包裹放入样板的输出槽，并像普通输出一样编码。提交合成请求时：

- 订单包裹的输出数量决定本次请求的目标数量；
- 合成计划会读取包裹中保存的目标资源；
- 订单包裹本身不会作为最终产物交付给玩家或网络；
- 虚拟输出适用于需要“请求某种资源”而不希望实际消耗或交付一个包裹物品的自动化流程；
- 目标资源仍必须存在可用配方、样板供应器和合成 CPU，否则请求会按普通 AE2 合成失败处理。

订单包裹可以作为处理样板或 Trinity 合成流程的虚拟输出。Trinity 会识别包裹中保存的目标 AEKey，并在计划中直接追踪目标资源；数量、输入材料和执行顺序仍由样板及合成计划决定。

## 标记包裹与普通包裹

三位一体结构预览和相关样板工具可以生成已经标记目标的订单包裹。标记包裹会在物品图标上显示目标提示，鼠标悬停时也会显示当前目标名称。

- **已标记包裹**：可以作为虚拟订单输出，目标由包裹数据组件确定；
- **未标记包裹**：没有目标，只能作为普通物品保存或重新配置；
- 修改目标不会改变包裹物品本身的数量，样板输出数量单独决定订单数量；
- 同一个包裹可以重新设置为另一种目标，重新编码样板后即可用于新的订单。

## 注意事项

- 订单包裹是不可堆叠物品，每个包裹单独保存自己的目标；
- 订单包裹不提供 AE 存储，也不会直接传输物品或流体；
- 它不能绕过配方、材料、工作站或合成 CPU 的可用性检查；
- 如果目标资源使用 Data Components、NBT 或其他精确键，包裹会保留完整 AEKey，不会自动忽略这些差异；
- 订单包裹的目标数据保存在物品组件中，携带、存入容器或写入样板时会随物品一起保存。
